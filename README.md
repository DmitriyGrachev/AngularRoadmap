# Angular Практикум

Личный курс для Java-разработчика, который начинает работать с Angular и хочет самостоятельно решать задачи Middle Fullstack: **два этапа, 12 недель, 60 занятий и практикумов, 180 часов**. Нагрузка — 15 обязательных часов и до 5 часов резерва в неделю. Java/Spring/JPA/SQL предполагаются знакомыми; главный акцент — frontend и его связь с backend.

Материалы и интерфейс на русском. В уроках есть объяснение механизма, связь с Java и границы этой аналогии, прогноз результата, разобранный пример, задача в IDE, три уровня подсказок и критерии самостоятельной проверки.

## Начать

Откройте PowerShell в `C:\ProjectsDirectory\Angular`. Нужен Node.js **22.22.3 или новее в ветке 22**; на этой машине проверен 22.23.2.

```powershell
npm.cmd ci
npm.cmd run site
```

Откройте **[учебный сайт](http://127.0.0.1:4300)** → «Начать первый урок». Для первого занятия откройте второй терминал в той же папке:

```powershell
npm.cmd run practice:web
```

Исходники первой задачи: `practice/foundations/web-basics/w1-01-ex1/index.html`. Откройте этот файл в своей IDE и следуйте уроку. Сервер практики: [127.0.0.1:4301/foundations/](http://127.0.0.1:4301/foundations/).

Если зависимости уже установлены, повторять `npm.cmd ci` перед каждым занятием не нужно. Терминалы с серверами оставляйте открытыми; остановка — Ctrl+C. В PowerShell используется `npm.cmd`, чтобы запуск не зависел от политики выполнения `.ps1`.

## Маршрут

| Неделя | Что изучаем | Что делаем |
|---|---|---|
| 1 | Браузер, HTML/CSS, DOM, события, массивы, формы | Маленький трекер на JavaScript |
| 2 | Модули, Promise, async/await, TypeScript, unknown, проверки | Типизированная обработка внешних данных |
| 3 | Компоненты, шаблоны, signals, DI, Router | Список и детали в Angular |
| 4 | HTTP, Observable, RxJS, отмена, тестирование сервиса | Поиск и состояния загрузки с Java API |
| 5 | Reactive Forms, валидация, POST/PATCH, серверные ошибки | Создание и редактирование заявок |
| 6 | Отладка, тесты, чтение существующего Angular-кода | Самостоятельная функция, проверка и объяснение решения |

Первый этап: пять занятий по 2 часа и один практикум на 5 часов в неделю. Второй этап: три занятия по 3 часа и практикум на 6 часов. Длинные занятия и практикумы делите на части. Дополнительные 0–5 часов — резерв. Если основа не закрепилась, используйте резерв и повторите упражнение на других данных.

| Неделя второго этапа | Теория | Практический результат |
|---|---|---|
| 7 | Асинхронность глубже, контракты TypeScript, браузер/CSS/доступность | Устойчивый клиентский модуль |
| 8 | Signal-store, Router, области DI и границы компонентов | Feature с явным владельцем состояния |
| 9 | Кэш RxJS, очереди записи, отмена и обработка ошибок | Экран, выдерживающий конкурирующие запросы |
| 10 | Сложные формы, динамические строки, CVA и UI-компоненты | Редактор с доступной валидацией |
| 11 | Контракты API, конфликты записей и безопасность | Изменение Angular + Java с проверкой отказов |
| 12 | Поведенческие тесты, производительность, доставка и инциденты | Самостоятельная функция и защита компромиссов |

Откройте [второй этап](http://127.0.0.1:4300/lessons/w7-01) после базового практикума. Добавлены **12 проверяемых упражнений и 12 ручных заданий**, включая шесть крупных практикумов. [Инструкция продвинутой практики](practice/middle/README.md). Итоговая оценка опирается на работу с новым требованием и объяснение решения; прохождение курса само по себе не присваивает грейд Middle.

Маршрут адаптирован под **PL2.2 / PL2.1: Angular 21.2.18, standalone и собственные сервисы состояния на Signals + RxJS**. В разборе UI учитываются Material/CDK, Bootstrap-обёртки и собственные компоненты PL2.2. Приоритеты и версии, включая PL1.26 на Angular 19, записаны в [профиле рабочего проекта](docs/environment.md). На сайте профиль виден в «Роадмапе», а привязка к PL — в уроках w1-01, w3-01, w3-03, w3-04, w4-04 и w6-01.

Учебная среда остаётся на **Angular 22.2.3 / TypeScript 6.0.3**, рабочая PL2 — на **Angular 21.2.18 / TypeScript 5.9.3**. Установка курса не меняет WEBC; новые API Angular 22 не являются требованиями рабочих заданий. Совместимость всей платформы с Angular 21 отдельно не проверялась. NgRx и PrimeNG не входят в обязательный маршрут; NgModules остаются краткой справкой для чтения чужого кода. Формы PL, Node, запуск и правила review ещё нужно уточнить.

## Практика и проверка

С третьей недели:

```powershell
npm.cmd run practice:angular
```

Откройте [учебный трекер](http://127.0.0.1:4302). Это заготовка с локальными данными и TODO. С четвёртой недели запустите в отдельном терминале `npm.cmd run practice:api`; нужен **JDK 21** в PATH. [Контракт и сценарии Java API](practice/issue-api/README.md).

Для разобранных примеров есть отдельная [песочница Angular](practice/angular-labs/README.md): `npm.cmd run practice:labs`, адрес [127.0.0.1:4304](http://127.0.0.1:4304). В уроках указан нужный пример, исходный файл и ожидаемый результат. Консольные TypeScript/RxJS-демонстрации запускаются своей командой из текста.

Упражнение `w1-04-ex1` выдаёт отчёт для сайта:

```powershell
npm.cmd run learn -- check w1-04-ex1
```

Нетронутая заготовка ожидаемо не проходит проверку. Исправляйте `practice/foundations/w1-04-ex1/solution.mjs`, запускайте снова и импортируйте указанный JSON из `practice/reports/` на странице «Прогресс». После изменения кода запускайте новую проверку.

Остальные задания оцениваются по критериям в уроках; некоторые дополнительно используют Node или Angular tests. Для Angular:

```powershell
npm.cmd run practice:test -- --watch=false
```

Начальный тест проверяет маршрутизацию заготовки. Новые тесты своих функций вы дописываете по урокам. Пройденные проверки не отмечают автоматически «прочитано» или «могу объяснить».

После собственной попытки можно посмотреть отдельный работающий пример:

```powershell
npm.cmd run practice:api
npm.cmd run practice:demo
```

Пример на [127.0.0.1:4303](http://127.0.0.1:4303) и его исходники в `author/solutions/issue-tracker` показывают итоговые механизмы. Если API уже работает, второй экземпляр запускать не нужно. Эталон и команды обслуживания не переписывают ваши решения.

## Лаборатория после уроков

Откройте [«Практику»](http://127.0.0.1:4300/training). В дополнение к основному курсу доступны:

| Раздел | Что внутри |
|---|---|
| 28 проверяемых упражнений | 16 базовых и 12 продвинутых: JavaScript, TypeScript, реальные Angular Signals, DI и Forms, RxJS, контракты API, гонки и качество тестов |
| 12 задач отладки | Независимые сломанные варианты, воспроизведение, три подсказки, разбор причины и регрессионный сценарий |
| 6 рабочих тикетов | Существующее приложение Service Desk: изучение чужого кода, ограничения, критерии приёмки и новое требование после первой попытки |
| 8 ревью | Небольшие изменения с контекстом; 3 можно принять, 5 требуют исправлений. Нужен собственный аргумент |
| 5 интерактивных механизмов | Event loop, гонка ответов RxJS, Signals, области DI и Reactive Forms; по два сценария, прогноз и выполнение по шагам |
| Журнал ошибок | Неверное предположение, объяснение механизма, другой пример и повторения |

Фильтр «После урока» связывает практику с изученной теорией. Задания «Вместо части практики» укладываются во время урока; «Дополнительно» — факультативны. Базовый этап занимает 90 часов; полный маршрут с продвинутым этапом — 180 часов. Ручные задания второго этапа открываются из самих уроков.

Проверяемое задание открывается в собственной папке. Например:

```powershell
npm.cmd run learn -- check checks-01
npm.cmd run learn -- check bug-01
```

У исходного незавершённого/сломанного решения ожидаются непройденные проверки. Исправляйте `solution.mjs` / `solution.ts`, затем запускайте снова. `starter.*` — неизменяемый исходный пример для тестов платформы. Эталоны находятся отдельно в `author/solutions`. JSON из `practice/reports` импортируется на странице «Прогресс». Всего поддерживается 41 задание с отчётами: первое упражнение курса, 28 базовых заданий лаборатории и 12 продвинутых `middle-01`…`middle-12`.

Для рабочих тикетов:

```powershell
npm.cmd run practice:workplace
```

[Service Desk на порту 4305](http://127.0.0.1:4305) уже умеет искать заявки, открывать карточки и сохранять форму. В нём локальный асинхронный API в памяти, без HTTP и постоянной базы. [Карта приложения и правила работы](practice/workplace/README.md). Тикеты выполняются вручную; существующие тесты приложения не заменяют проверку их новых критериев.

## Прогресс

На сайте отдельно учитываются чтение, импортированные попытки и ваша самооценка. После отметки понимания тема появляется на повторении через 2 и 7 дней. Любой готовый урок можно открыть напрямую.

Прогресс хранится в конкретном браузере по адресу `127.0.0.1:4300`. Экспортируйте копию на странице «Прогресс», особенно перед сменой браузера или очисткой его данных. Импорт сначала показывает результат объединения и предлагает выбрать конфликтующие записи. История попыток сохраняется, одинаковые отчёты не дублируются.

[Журнал ошибок](http://127.0.0.1:4300/journal) хранит попытки лаборатории, разборы ошибок и самостоятельные объяснения отдельно от прежнего прогресса. У него свой экспорт/импорт. Повторяйте через 2 дня и ещё через 5 дней после первого успешного повторения: при соблюдении расписания это дни 2 и 7. Один поздний ответ не засчитывает две разнесённые проверки памяти. Просроченные ошибки предлагают новый пример на странице «Сегодня». Ни разбор, ни успешные тесты автоматически не отмечают освоение урока.
