# JavaScript: данные, функция и событие

**Результат:** нажатие меняет состояние заявки и видимый текст; вы объясняете тот же путь в маленьком Angular-фрагменте. Нужны [HTML и DOM](/lessons/w1-01), [основы CSS](/lessons/w1-02). На Angular здесь смотрим как на следующий способ организации уже знакомого поведения.

## Рабочая ситуация и прогноз

Кнопка «В работу» должна изменить статус с `OPEN` на `IN_PROGRESS`. HTML создал кнопку, CSS оформил её, теперь понадобится выполняемый код.

```js
let status = 'OPEN';
function startWork() {
  status = 'IN_PROGRESS';
}
console.log(status);
startWork();
console.log(status);
```

Назовите две строки вывода. Произойдёт ли изменение при одном объявлении функции без `startWork()`? Увидит ли пользователь новый текст, если код поменяет только переменную? Сохраните прогноз, затем сравните его с механизмом.

## Значение, имя и выполнение

JavaScript в браузере выполняет поведение страницы. Сейчас используем строки, логические значения и функции. Строка — последовательность символов в кавычках. Значение `true` или `false` описывает логическое условие. `console.log` вызывает функцию вывода в DevTools Console; это не элемент на странице.

Объявление `let status = 'OPEN'` связывает имя с начальным значением. Позднее присваивание `status = 'DONE'` меняет эту связь. `const` запрещает повторное присваивание имени после инициализации. Выбирайте `const`, если имя не должно получать другое значение, и `let`, если изменение является частью сценария. `const` не делает объект глубоко неизменяемым; объекты подробно разберём в следующем уроке. JavaScript не требует указывать тип переменной в таком объявлении, но значения всё равно имеют тип во время выполнения.

Функция — вызываемый участок кода. Объявление сохраняет поведение, а круглые скобки после имени выполняют его. Параметры принимают вход, `return` возвращает результат вызывающему коду. Отсутствие `return` даёт `undefined`, специальное значение отсутствующего результата. Для обработчика, задача которого изменить интерфейс, возвращаемое значение часто не нужно.

Условие `if` выбирает ветку по логическому результату. Для сравнения статусов используйте `===`: это сравнение без неявного преобразования типов. Оператор `=` присваивает значение, он не проверяет равенство. Например, `if (status === 'OPEN')` проверяет текущий статус, а запись с одним `=` может случайно изменить данные внутри условия. Такая опечатка способна выглядеть как работающая логика, поэтому прогнозируйте не только видимый итог, но и промежуточные значения.

## Как событие связывает пользователя и код

`document.querySelector('#status')` ищет первый DOM-элемент по CSS-селектору. `#status` означает id. Если элемент не найден, возвращается `null`, то есть явное отсутствие объекта. В разобранном примере script стоит после нужной разметки: элементы к моменту выполнения уже существуют. Если опечататься в id, обращение к `textContent` у `null` даст ошибку. Это сигнал проверить разметку и селектор, а не повод подавлять все ошибки.

`element.textContent` — свойство текстового содержимого элемента. Присваивание новой строки меняет DOM. Переменная JavaScript сама по себе с ним не связана: сначала меняем данные, затем явно обновляем текст. Использование `textContent` также означает, что пользовательский текст не интерпретируется как HTML. Для вывода названия заявки это подходящий базовый инструмент.

`button.addEventListener('click', startWork)` регистрирует обработчик — функцию, которую браузер вызовет при клике. Здесь передаётся сама функция, без скобок. Запись `startWork()` вызвала бы её немедленно во время установки обработчика. Позже браузеру пришлось бы передать её результат вместо функции. Событие может возникнуть от мыши или клавиатурной активации настоящей кнопки.

Путь выполнения теперь точный: браузер создаёт DOM → скрипт находит элементы → регистрирует функцию → пользователь активирует кнопку → браузер вызывает функцию → меняются данные → обновляется DOM. До события обработчик ожидает вызова, а остальной код может завершиться. Не нужно писать бесконечный цикл ожидания: он только заблокирует страницу.

## Мост от Java

Функция похожа на метод по входам и результату, но может существовать вне класса и передаваться как значение. Обработчик напоминает listener в Java UI. При этом переменная `status` живёт в браузере и не меняет поле серверного Java-объекта. Когда появится API, для сохранения потребуется отдельный HTTP-запрос. Сейчас обновление вкладки вернёт исходное значение, заданное в файле.

## Разобранный пример и первый взгляд на Angular

Откройте [события](http://127.0.0.1:4301/foundations/web-basics/examples/events.html), исходник `practice/foundations/web-basics/examples/events.html`. При открытии виден `OPEN`. Один клик даёт `IN_PROGRESS` в абзаце и Console; кнопка становится недоступной, потому что `disabled` получает `true`. Обновление страницы снова показывает `OPEN`. Уберите в эксперименте строку `output.textContent = status`: данные изменятся, старый текст останется. Затем верните строку.

Прочитайте `practice/foundations/web-basics/w1-03-ex1/angular-reading.txt`. Это фрагмент для чтения, а не самостоятельная программа: ему нужны Angular и импорт `Component`. Декоратор `@Component` сообщает Angular, какой шаблон связан с классом. `status` — данные экземпляра. `{{ status }}` выводит значение в шаблон, `(click)="complete()"` связывает событие с методом. Angular обновляет представление по правилам своей системы; вручную искать абзац здесь не требуется. Пока достаточно найти три места: данные, отображение, обработчик. Создание такого компонента будет на неделе 3.

## Критерии

- До действия `OPEN`, после одного действия `DONE`; кнопка выключена после завершения.
- В Console нет ошибок, после перезагрузки исходное состояние воспроизводится.
- Обработчик передан функцией и не выполняется при первоначальной загрузке.
- Вы находите данные, шаблон и обработчик в Angular-фрагменте и объясняете последовательность.
