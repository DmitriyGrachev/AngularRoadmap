# Преобразовать Page<T> без потери типов

Урок w2-04, около 30 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

При преобразовании DTO в модель представления меняются элементы страницы, но page/total остаются прежними. Два параметра типа связывают callback T→U с результатом Page<U>. Это похоже на Java Function<T,U> и Stream.map; TypeScript выводит U из callback. Generic не проверяет внешний JSON: эта функция работает уже после валидации.

### Контракт API

Экспортируйте interface Page<T>{items:readonly T[];page:number;total:number} и mapPage<T,U>(page:Page<T>,transform:(item:T)=>U):Page<U>. Вызовите transform один раз на элемент в исходном порядке, верните новый объект и массив, сохраните page/total, не мутируйте вход. Для пустой страницы callback не вызывается. Тип результата должен выводиться без any.

### Пример и новая проверка

[2,5] после n=>String(n) даёт ["2","5"] с прежними метаданными. Новый пример: из {id:"AB"} получите длину id; output.items[0] имеет тип number.

## Условия приёмки

- T связан с аргументом callback, U — с результатом.
- Порядок, метаданные и число вызовов сохранены.
- Замороженный вход и пустая страница поддерживаются.
