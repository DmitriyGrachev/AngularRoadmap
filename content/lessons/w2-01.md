# Функции как значения, замыкания и модули

**Результат:** вы разделяете данные и преобразования по файлам и объясняете, когда передаётся функция, а когда выполняется вызов. Нужны [события](/lessons/w1-03) и [массивы](/lessons/w1-04). Выделите 20 минут на собственный прогноз и запуск, 30 на механизм, 45 на задание и 25 на разбор ошибки и новую вариацию.

## Рабочая ситуация и прогноз

Две страницы должны использовать одинаковое преобразование заявок. Копирование кода мешает исправлениям; функции можно вынести в отдельный модуль. Одновременно сломался обработчик: сообщение появляется при старте, а не во время обхода массива.

```js
function makeCounter() {
  let count = 0;
  return () => {
    count += 1;
    return count;
  };
}
const first = makeCounter();
const second = makeCounter();
console.log(first(), first(), second());
```

Получится `1 2 1` или `1 2 3`? Почему count ещё существует, хотя makeCounter уже завершилась? Не запускайте код до объяснения своего предположения.

## Функция передаётся как значение

Функцию можно положить в переменную, вернуть из другой функции и передать аргументом. Callback — функция, которую получивший её код вызывает по своему договору. Не каждый callback асинхронен. `issues.forEach(printTitle)` сразу проходит массив и вызывает printTitle для каждого элемента; callback клика вызывается позже браузером. Метод forEach нужен для действий над элементами, возвращает undefined и не строит новый массив, в отличие от map.

В записи `printTitle(issues[0])` скобки выполняют функцию немедленно. Её результат затем подставляется во внешний вызов. Если printTitle только пишет в Console, результат undefined. Поэтому `issues.forEach(printTitle(issues[0]))` сначала напечатает название первой заявки, затем выбросит ошибку: forEach требовалась функция, а получил undefined. Не пытайтесь исправлять это случайной задержкой; неверно передан аргумент.

Стрелка `issue => issue.title` создаёт функцию с одним параметром и неявным возвратом. Запись `issue => { return issue.title; }` делает то же с явным телом. Фигурные скобки меняют синтаксис возврата: `issue => { issue.title; }` ничего не возвращает. Если нужно сразу вернуть объект, используйте круглые скобки вокруг литерала, например `issue => ({title: issue.title})`, чтобы отличить объект от тела функции.

## Область видимости и замыкание

Область видимости определяет, какие имена доступны в данном месте кода. `let` и `const` ограничены блоком `{...}`; параметры функции и её локальные переменные не становятся автоматически глобальными. Вложенная функция видит переменные внешней области. Она сохраняет доступ к этим связям даже после окончания внешнего вызова. Это замыкание.

В прогнозе каждый вызов makeCounter создаёт отдельную локальную count. Переменная first содержит функцию с доступом к первой count, second — к другой. Два вызова first меняют одну и ту же связь: 1, затем 2. Первый вызов second начинает с 0 и даёт 1. Замыкание захватывает доступ к переменной, а не просто фотографию её начального значения. Если внутри внешней области значение меняется, последующий вызов видит изменение.

Так можно сохранять небольшое приватное состояние, например число вызовов. Однако не стоит прятать в десятках замыканий всё состояние приложения: позднее нам понадобится понятное место данных в сервисе или компоненте. Здесь цель — понимать обработчик, который использует переменную из окружения.

## this зависит от способа вызова

У обычной функции this определяется вызовом. Для `object.method()` им обычно является object; передача `object.method` как отдельного callback теряет эту связь. В JavaScript-модуле отдельный вызов обычной функции получает this равным undefined. Метод, читающий `this.title`, тогда упадёт. Сходство с Java-методом на этом заканчивается: извлечённая функция не навсегда привязана к экземпляру.

Стрелочная функция не создаёт собственного this, а берёт его из окружающей лексической области. Она удобна для обёртки `() => object.method()`: внутри явно вызывается нужный метод на object. Но стрелка сама по себе не делает любой this правильным. В верхнем уровне модуля this — undefined, поэтому стрелка оттуда не получит магически «текущую заявку». Предпочитайте явные аргументы там, где скрытый контекст не нужен.

## Короткая запись данных и модули

Деструктуризация `const {title} = issue` читает свойство title в одноимённую переменную. Это не удаление свойства и не глубокое копирование объекта. В параметре `({title}) => title` сначала извлекается поле переданного объекта. Если объект отсутствует, деструктуризация не исправляет отсутствие автоматически.

Модуль — файл с явными экспортами и импортами. `export const issues = ...` делает имя доступным другим файлам; `import {issues} from './model.mjs'` связывает его в текущем. Относительный путь начинается с `./`, расширение `.mjs` явно обозначает JavaScript-модуль в Node. В браузере модуль подключают через `script type="module"` и сервер. Модули имеют собственную область видимости: случайное имя из соседнего файла не появляется автоматически.

## Мост от Java и разобранный пример

Импорт напоминает Java import только организацией зависимостей. Он не превращает файл в класс и не требует класса для каждой функции. Замыкание напоминает lambda с захваченным окружением, но локальная let в JavaScript может изменяться; ограничение Java effectively final переносить нельзя.

Выполните `node practice/foundations/async-types/examples/modules/main.mjs`. Ожидаются две строки: `Письмо 1 2` и `Письмо, Кнопка`. model.mjs экспортирует данные, main.mjs их импортирует, счётчик хранит count, map извлекает названия. Для изменения одного условия создайте второй счётчик и вызовите его один раз: он должен дать 1 независимо от первого.

## Критерии

- Скрипт завершается без ошибки; каждое название выводится один раз во время обхода.
- Преобразование экспортируется и импортируется, OPEN даёт одну заявку, исходный массив сохранён.
- Два счётчика дают `1, 2` и `1`; вы объясняете отдельные окружения.
- Вы объясняете различие функции, её вызова и callback без запуска.
