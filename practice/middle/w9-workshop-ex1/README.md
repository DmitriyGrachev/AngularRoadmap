# Кэш, очередь сохранений и сохранность черновика

Ручное задание к уроку [w9-workshop](../../../content/lessons/w9-workshop.md). Добавить кэш карточек и очередь подтверждённых снимков формы, не теряя новый ввод при старом ответе.

## Где работать

Реализация находится в вашей версии `practice/workplace`: src/app/detail-page.ts/html, сервис кэша/очереди, модели команд и связанные spec-файлы. Эта папка задания хранит только условия и `notes.md` с доказательствами. Наличие заполненных заметок само по себе не подтверждает работу функции. Не заменяйте свои исходники авторским решением; сохраните предыдущие выполненные изменения.

```text
npm.cmd run practice:workplace
npm.cmd run test:workplace
npm.cmd run build:workplace
```

Адрес: http://127.0.0.1:4305. DeskApi — асинхронный сервис в памяти: запросов GET/PATCH в Network нет, reload восстанавливает seed. Для порядка и числа операций используйте управляемый fake API или spy. Это не проверка HTTP, БД или двух серверных клиентов. Страница начинается с 1, статусы — open/in-progress/closed; не переносите контракт middle-04 без адаптации.

## Требования

1. У команды есть собственный ID, ID заявки и независимый снимок примитивных полей RequestPatch.
2. Записи стартуют последовательно; отказ одной даёт её результат и не уничтожает следующую.
3. Не больше трёх ожидающих команд; отказ принять новую не очищает черновик.
4. Успех инвалидирует карточку и необходимые данные списка. Старое чтение не становится актуальным после инвалидации.
5. Ответ предыдущей команды не перезаписывает более новый draft; успех не определяется по finalize.
6. Очередь принадлежит карточке: уход прекращает активную подписку и не запускает ожидающие команды; граница модели явно описана.

## Проверка на новых данных

- A=VPN success, B=DNS error, новый неподтверждённый draft=почта.
- Два одновременных чтения ID и одно выполнение загрузчика.
- Инвалидация между старым и новым чтением.
- Три ожидающие команды, четвёртая отклонена без потери текста.
- Уход с карточки при активной записи.

До кода запишите ожидаемое поведение, затем реализуйте и сравните результат. Если временные свойства проверяются тестом, управляйте завершением операций вручную; случайные задержки не доказывают отсутствие гонки. Baseline-тесты не являются оценкой новой функции.

## Что сохранить в notes.md

Временная таблица draft/commands/confirmed/cache, тест последовательности и отказа, тест сохранности ввода, тест поколений кэша и ручной маршрут. Укажите команды и фактический результат, а также ограничения. Не копируйте служебные исходники и реальные данные работодателя.

## Рубрика

По каждому требованию отметьте «самостоятельно», «с подсказкой» либо «нужна повторная попытка» и приведите наблюдаемое доказательство. Обязательные свойства нельзя компенсировать красивым интерфейсом или количеством тестов. Полные критерии и три последовательные подсказки находятся в уроке. Для этой задачи автоматического выставления оценки через `learn check` нет; после собственной попытки выполните ручную проверку и отметку в платформе.
