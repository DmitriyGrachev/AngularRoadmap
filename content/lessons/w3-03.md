# Signals: исходное и вычисляемое состояние

120 минут. Результат: фильтр и счётчик согласованы с исходным массивом без ручной синхронизации. Нужны [границы компонентов](/lessons/w3-02) и [копирование объектов](/lessons/w1-04).

## Ситуация и прогноз

Список заявок хранится отдельно, отфильтрованный список — отдельно, счётчик — ещё в одном поле. После закрытия заявки строка обновилась, а число осталось прежним. Сколько мест теперь нужно исправить? Предскажите поведение `const n = signal(2); const twice = computed(() => n() * 2); n.set(3)`. Когда читатель снова запросит `twice()`, ожидается шесть. Отдельная команда обновления счётчика не нужна.

## Ячейка и зависимость

Signal хранит значение и сообщает потребителям о его изменении. Чтение выглядит как вызов функции: `count()`. Это не случайный синтаксис: во время чтения Angular может запомнить зависимость. `set` заменяет значение целиком, `update` получает предыдущее и возвращает следующее. Если следующее значение зависит от предыдущего, `update(n => n + 1)` выражает это явно.

`computed` хранит вычисление, основанное на прочитанных signals. У него нет публичного `set`: результат определяется источниками. Вычисление ленивое и кэшируется. Пока исходные зависимости не изменились, повторное чтение не обязано повторять дорогую работу. После изменения зависимость помечается устаревшей, и следующее чтение получает актуальный результат. Это помогает держать одну достоверную версию исходных данных.

Зависимости определяются фактическими чтениями. Если ветка `if` не прочитала signal, в данном проходе такой зависимости нет. Поэтому формулируйте вычисление как обычную чистую функцию: прочитать источники, вернуть результат. Не отправляйте HTTP и не вызывайте `set` другого состояния внутри `computed`. Побочные действия делают порядок вычислений частью бизнес-логики и создают трудно заметные циклы.

Signal не превращает объект в глубокий proxy. Вызов `items()[0].done = true` меняет обычный объект, но не сообщает signal о новом значении. По умолчанию сравнение использует `Object.is`, поэтому `items.set(items())` с той же ссылкой тоже не является надёжным способом уведомления. Создавайте новый массив и новый объект для изменённой записи. Неизменённые объекты можно оставить прежними: глубокое копирование всего дерева обычно не требуется.

## Разобранная демонстрация

Полный файл: `practice/angular-labs/src/demos/w3-03.ts`. Запустите из корня `npm.cmd run practice:labs`, откройте `http://127.0.0.1:4304/w3-03`. Демонстрация уже подключена отдельно от вашего трекера. Ожидаются две книги и один непрочитанный экземпляр; фильтр и действие «Прочитано» приводят к пустому набору и нулевому счётчику. Никаких FormsModule и ручных DOM-запросов здесь нет.

```ts
import { Component, computed, signal } from '@angular/core';

@Component({
  selector: 'library-state-demo', standalone: true,
  template: `
    <button type="button" (click)="toggleUnread()">
      Только непрочитанные: {{ onlyUnread() }}
    </button>
    <p>Непрочитанных всего: {{ unreadCount() }}</p>
    @for (book of visible(); track book.id) {
      <p>{{ book.title }}
        <button type="button" (click)="read(book.id)">Прочитано</button>
      </p>
    } @empty { <p>Подходящих книг нет</p> }
  `,
})
export class LibraryStateDemo {
  books = signal([
    { id: 'a', title: 'Сети', read: false },
    { id: 'b', title: 'Java', read: true },
  ]);
  onlyUnread = signal(false);
  toggleUnread() { this.onlyUnread.update(value => !value); }
  visible = computed(() => this.books().filter(
    book => !this.onlyUnread() || !book.read,
  ));
  unreadCount = computed(() => this.books().filter(book => !book.read).length);
  read(id: string) {
    this.books.update(books => books.map(book =>
      book.id === id ? { ...book, read: true } : book,
    ));
  }
}
```

Сначала показаны две книги и счётчик один. Включение фильтра оставляет «Сети». Нажатие «Прочитано» удаляет её из видимого списка и уменьшает общий счётчик до нуля. При отключении фильтра обе книги снова видны. Исходный массив и видимый массив выполняют разные роли: первый хранит всё, второй является представлением для текущего условия.

Измените `read` на прямую мутацию и повторите сценарий. Даже если какая-то часть шаблона обновится вследствие другого события, вычисляемое значение может остаться кэшированным: signal не получил нового значения. Такой частичный успех опаснее явной ошибки. Верните `update` с новым массивом и проверьте все потребители, а не только текст одной карточки.

## Мост от Java и границы применения

`computed` напоминает getter, но обычный Java getter не регистрирует зависимости и не инвалидирует кэш автоматически. Signal также не является `AtomicReference`: он не решает вопросы многопоточности сервера. Его задача — реактивное состояние браузерного интерфейса. И это не хранилище на диске: перезагрузка создаёт начальные значения заново.

Вычислять счётчик из списка полезно, пока список действительно содержит весь набор. После перехода к серверной пагинации длина текущей страницы не равна количеству всех заявок. Тогда общее число приходит отдельным `total` по контракту API. Механизм computed остаётся тем же, но смысл источника меняется. Правильный тип не исправляет неверную предметную интерпретацию данных.

Локальный signal уместен для раскрытой панели или текущего выбора, который нужен одному компоненту. Не переносите всё в глобальный сервис автоматически. Общий сервис понадобится, когда несколько независимых ветвей должны согласованно читать и изменять одни данные. Само наличие реактивности не определяет владельца состояния.

## Как читать StoreService в PL

По переданному разбору PL2.2/PL2.1, приложение использует Angular 21.2.18 и собственный `StoreService` с `signal`/`computed`. Учебная площадка работает на Angular 22.2.3; разобранные здесь операции signals доступны и в целевой версии 21. Курс не предполагает перенос новых API из документации 22 в рабочий проект.

В вашем примере `mapsTab = signal<MapsTab>('MANAGE')` — исходное состояние: какая вкладка выбрана сейчас. Выражение `computed(() => this.store.mapsTab())` даёт читаемое представление того же значения. Оно не создаёт независимую редактируемую вкладку и не содержит отдельного бизнес-расчёта. Для сравнения, `computed(() => this.store.mapsTab() === 'MANAGE')` уже преобразует значение в признак. В обоих случаях чтение регистрирует зависимость, но назначение вычисления различается. Не заменяйте принятый в команде способ доступа только потому, что вычисление выглядит коротким.

Состояние отвечает «что выбрано сейчас?», событие — «что произошло?». Два клика по уже выбранной вкладке могут быть двумя событиями, но `set('MANAGE')` при текущем `'MANAGE'` не создаёт двух изменений состояния. Поэтому обработку каждой команды «обновить» нельзя строить только на изменении signal вкладки. В PL для запросов и событий используется RxJS; его соединение с текущим состоянием разберём в [уроке поиска](/lessons/w4-04). Создавать NgRx ради общего signal здесь не требуется.

## Критерии ручной проверки

Нет вручную синхронизируемой копии счётчика; фильтрация не уничтожает исходный набор; обновление создаёт новые ссылки; пустой результат понятен; вы воспроизводите дефект мутации и объясняете исправление. На примере вкладки различаете событие, исходное состояние и вычисляемое представление.
