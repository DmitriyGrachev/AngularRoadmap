# Signals store: владелец состояния и проверяемые инварианты

180 минут: 40 на модель, 25 на пример, 85 на упражнение и 30 на защиту. Предыдущий шаг — [устойчивый клиентский модуль](/lessons/w7-workshop). Результат: небольшой store на Angular Signals управляет состоянием через команды, а производные значения остаются согласованными.

## Сначала решите, что является фактом

На странице есть список заявок и выбранная заявка. Если хранить одновременно items, selectedId и отдельный selectedItem, появляются три места изменения. После переименования строки список покажет новое название, панель справа — старое. После удаления строки панель может показывать запись, которой уже нет. Проблема не в Signals: модель содержит копию значения, которое можно вывести из двух исходных фактов.

Храните список и выбранный ID, а выбранную строку вычисляйте. Инвариант формулируется так: selectedId равен null либо указывает на существующую строку; selected отражает актуальную строку с этим ID. Команда замены списка обязана проверить выбор. Команда переименования меняет строку, но не ID. Если эти правила спрятаны в нескольких компонентах, любой новый компонент может забыть одно из них. Поэтому writable signals закрывают внутри сервиса, наружу дают чтение и осмысленные команды.

Signal хранит значение и уведомляет зависимых потребителей об изменении. Computed выводит значение из прочитанных signals, вычисляется лениво и запоминает результат до изменения зависимости. Зависимости определяются фактическим чтением: ветка, которая не читает items, не зависит от items в этом вычислении. Это не подписка «на все поля объекта». Изменение вложенного объекта без set/update может остаться невидимым механизму реактивности.

Readonly signal запрещает публичные set и update, но не замораживает вложенный массив. Код `store.items().push(...)` всё ещё может изменить данные, если тип и объект это допускают. Используйте readonly-типы на границе и неизменяемые переходы, а не обещайте абсолютную защиту одним asReadonly. Runtime freeze бывает полезен в диагностике, но глубокое замораживание каждого большого ответа не нужно добавлять без причины.

## Команды сохраняют границу изменения

`rename(id, title)` сообщает намерение. `setState(anything)` позволяет вызывающему нарушить любой инвариант. Для небольшого feature-сервиса достаточно нескольких методов; огромная универсальная библиотека действий и редьюсеров не обязательна. Важнее, чтобы переход был обозримым: один изменяемый массив, один выбранный ID и одна производная строка. Бизнес-правила, пришедшие с сервера, не следует независимо дублировать в пяти computed.

При изменении одной строки создаётся новый массив и новый объект этой строки. Остальные объекты могут сохранить ссылки. При команде, которая ничего не меняет, сохраняйте прежнюю ссылку массива. Это не только оптимизация: она делает смысл no-op явным и уменьшает лишние вычисления. Но сравнение по ссылке не заменяет доменную корректность. Новый объект с прежним ID всё ещё может содержать новые данные, и computed selected должен отразить их.

Для Java аналогией служит агрегат с закрытым состоянием и публичными методами. Однако Angular service не равен singleton Spring bean автоматически: его область зависит от места provider. И signal не JPA-managed entity: мутация поля не запускает dirty checking, который сохранит его в базу. Не ждите от реактивности ни транзакции, ни сетевой синхронизации. Store в этом уроке управляет локальным представлением; сохранение на сервере будет отдельной командой с состоянием ожидания и отказа.

## Разобранный пример

Сохраните `signal-demo.mjs` в корне своей рабочей копии репозитория, чтобы импорт нашёл установленные зависимости. Запустите `node signal-demo.mjs`; после разбора временный файл можно удалить. Браузер, Angular bootstrap и Java API не нужны:

```js
import { signal, computed } from '@angular/core';
const books = signal([{ id: 'a', title: 'HTTP' }, { id: 'b', title: 'SQL' }]);
const activeId = signal('a');
const active = computed(() => books().find(book => book.id === activeId()) ?? null);
console.log(active().title);
books.update(rows => rows.map(row => row.id === 'a' ? { ...row, title: 'HTTP/2' } : row));
console.log(active().title);
activeId.set('b');
console.log(active().title);
```

Ожидаются HTTP, HTTP/2 и SQL. Ни один callback не присваивает active вручную. Измените пример, сохранив объект active до переименования: старая ссылка содержит прежнее значение, новое чтение computed — обновлённое. Это ожидаемая работа неизменяемых снимков, а не ошибка кэширования.

Не добавляйте effect, который читает список и копирует найденную строку в ещё один writable signal. Такая синхронизация создаёт дополнительное состояние и дополнительные моменты несогласованности. Effect нужен для взаимодействия с внешним нерективным API, когда такая граница действительно существует; вычисление строки по ID выражается computed. Также не превращайте signal в поток и обратно только ради простого синхронного свойства. RxJS пригодится там, где важны события, время, конкуренция и отмена.

## Практика в IDE — middle-03

Откройте `practice/middle/middle-03/README.md` и `solution.mjs`. Реализуйте `createSelectionStore(items)` на настоящих Angular signals. Публичное чтение: items, selectedId и selected; команды: select(id|null), replace(items), rename(id,title). Выбор неизвестного ID игнорируется. Замена списка сохраняет существующий выбранный ID и очищает исчезнувший. Переименование неизвестного ID или в прежнее название — no-op с прежней ссылкой items. Изменение выбранной строки должно сразу отражаться в selected.

Запуск проверки: `npm.cmd run learn -- check middle-03`. Перед реализацией составьте последовательность из шести команд и ожидаемые значения после каждой. После первой рабочей версии проверьте ссылки неизменённых строк. Не усложняйте контракт DTO-валидацией из прошлого урока: упражнение принимает уже подготовленные данные. В Angular-приложении decoder должен отработать до передачи массива в store.

## Критерии самопроверки

Обязательны согласованный выбор, неизменяемость обновления и no-op без новой ссылки. Самостоятельное решение объясняет, почему computed выбран вместо effect, где проходят границы изменения и почему asReadonly не защищает вложенный объект. Для переноса в PL найдите небольшой существующий Signals-сервис и запишите один инвариант без копирования рабочих исходников. Оцените, есть ли в нём производное дублированное состояние; изменение чужого сервиса в рамках урока не требуется.
