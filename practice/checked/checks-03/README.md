# Сузить union по состоянию загрузки

Урок w2-03, около 30 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

Независимые loading/error/data допускают противоречивые комбинации. Union перечисляет только допустимые состояния, а switch по kind открывает поля нужного варианта. Это похоже на sealed hierarchy и pattern matching в Java. Строковый kind существует в runtime, интерфейсы удаляются; optional-поля в общем интерфейсе ослабили бы контракт.

### Контракт API

В solution.ts экспортируйте Issue={id:string,title:string,status:"OPEN"|"IN_PROGRESS"|"DONE"}, LoadState={kind:"idle"}|{kind:"loading"}|{kind:"ready",items:readonly Issue[]}|{kind:"error",message:string} и describeLoad(state:LoadState):string. Тексты: idle → "Не загружено", loading → "Загрузка", ready → "Заявок: N", error → "Ошибка: MESSAGE". Не используйте any; strict-компилятор должен отклонять ready без items и неизвестный kind.

### Пример и новая проверка

{kind:"ready",items:[]} даёт "Заявок: 0". Новый пример: message="403" должна сохраниться в "Ошибка: 403", без доступа к items.

### Работа

Из корня проекта выполните `npm.cmd run learn -- check checks-03`. Редактируйте только `practice/checked/checks-03/solution.ts`. Сначала запишите прогноз или собственную попытку в тренажёре. Отчёт сохраняется в practice/reports и не отмечает урок освоенным автоматически.

## Условия приёмки

- Все четыре состояния дают определённый текст.
- Union отклоняет ready без items и неизвестный kind.
- Проходят runtime и отдельная strict-компиляция потребителя.
