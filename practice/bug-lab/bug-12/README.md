# bug-12: Двойное нажатие создало две заявки

Связанный урок: [w5-03](../../../content/lessons/w5-03.md). Около 30 минут; упражнение может заменить часть ручной практики урока.

Симптом: быстрый двойной клик «Сохранить» создаёт две записи. Выполните node practice/bug-lab/bug-12/repro.mjs: два DTO приходят до завершения первого save, который до правки вызывается дважды. Исправьте saveRequests: пока запись активна, новые нажатия игнорируются; после успеха или отказа разрешена новая самостоятельная попытка.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-12/repro.mjs
npm.cmd run learn -- check bug-12
```

Сценарий работает без сайта, dev server и Java API с установленными зависимостями проекта. Исходный дефект намеренно завершает repro с AssertionError и ненулевым кодом. После исправления сценарий завершается успешно. Полная проверка создаёт отчёт версии 1 для учебного сайта.

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

saveRequests(submits$, save) возвращает Observable результатов. save(dto) возвращает Observable созданного объекта. Пока inner активен, события нужно игнорировать, не запоминать и не отменять первую запись.

## Критерии результата

- Два submit во время одного ожидания вызывают save один раз.
- Игнорированный дубль не отправляется позднее из очереди.
- Ошибка выдаёт { ok: false, message } и разрешает новую попытку; успех выдаёт { ok: true, item }.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: двойной клик → 503 → новая осознанная отправка → успех. Всего должны произойти два save. Объясните, почему последовательные два POST через concatMap всё ещё нарушают требование.
