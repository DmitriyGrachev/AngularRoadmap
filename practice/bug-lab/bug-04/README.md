# bug-04: В массиве две заявки, computed показывает одну

Связанный урок: [w3-03](../../../content/lessons/w3-03.md). Около 30 минут; упражнение может заменить часть ручной практики урока.

Симптом: после add список содержит новую заявку, а openCount() остаётся прежним. Выполните node practice/bug-lab/bug-04/repro.mjs: сначала прочитайте computed, затем добавьте OPEN. Первое чтение только после мутации могло бы скрыть дефект. Исправьте add и setStatus, сохранив старые снимки массива и объектов.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-04/repro.mjs
npm.cmd run learn -- check bug-04
```

Сценарий работает без сайта, dev server и Java API с установленными зависимостями проекта. Исходный дефект намеренно завершает repro с AssertionError и ненулевым кодом. После исправления сценарий завершается успешно. Полная проверка создаёт отчёт версии 1 для учебного сайта.

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

createBoard(initial) возвращает { issues: Signal<Issue[]>, openCount: Signal<number>, add(issue), setStatus(id, status) }. Заявка содержит id и status.

## Критерии результата

- После предварительного чтения openCount добавление OPEN увеличивает счётчик.
- Смена OPEN на DONE уменьшает счётчик; неизвестный ID ничего не удаляет.
- Замороженный вход допустим; входные объекты и предыдущие снимки не меняются.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: сохраните снимок до добавления и ещё один до смены статуса. После обеих команд проверьте каждый снимок и новый computed. Объясните, почему единственное первое чтение computed в конце не обнаруживает этот дефект.
