# Компонент: данные, шаблон и событие

120 минут. Результат: вы переносите список в Angular и объясняете, почему нажатие меняет экран. Нужны [объекты и массивы](/lessons/w1-04), [типы](/lessons/w2-03) и [события HTML](/lessons/w1-05).

## Ситуация и прогноз

В обычном JavaScript вы искали узел DOM и записывали в него текст. Теперь разметкой управляет Angular. Представьте кнопку `[disabled]="busy"` при `busy = false`. Будет ли она заблокирована? А если написать `disabled="false"`? Сначала запишите прогноз. В первом случае Angular присваивает булево свойство DOM; во втором браузер видит присутствующий HTML-атрибут, поэтому блокирует кнопку. Одинаковые на вид строки описывают разные операции.

## Как устроен компонент

Компонент соединяет TypeScript-класс, шаблон и настройки. `@Component` — декоратор: он сообщает Angular, какой класс является компонентом, где его шаблон и как его включить в другой шаблон. Объект параметров называют metadata. Это описание для компилятора и среды Angular, а не дополнительный пользовательский объект заявки.

`selector` задаёт имя HTML-элемента, например `app-library`. Когда родитель использует такой элемент, Angular создаёт экземпляр класса и его представление. Два элемента означают два экземпляра с отдельными полями. `template` содержит разметку прямо в строке; `templateUrl` указывает соседний HTML-файл. Маленький пример удобно читать целиком, рабочую страницу удобнее разделять. Относительный путь отсчитывается от файла компонента.

В курсе компоненты самостоятельные — standalone. Если шаблон использует другой компонент или pipe, зависимость включают в `imports` родителя. Импорт TypeScript в начале файла делает имя доступным коду; запись в metadata делает компонент доступным шаблону. Это две разные операции. Встроенные блоки `@if` и `@for` дополнительных импортов не требуют.

Интерполяция `{{ expression }}` превращает результат выражения в отображаемый текст. Angular экранирует строку: название `<strong>Книга</strong>` будет текстом, а не исполняемой разметкой. Property binding `[title]="book.name"` присваивает DOM-свойство. Event binding `(click)="choose(book.id)"` вызывает обработчик при событии. Данные идут из класса в представление; событие сообщает классу о действии. Браузерное событие доступно как `$event`, но передавать его дальше стоит только когда он действительно нужен.

Шаблон — описание желаемого интерфейса для текущих данных. Он не выполняется один раз при старте. Angular обновляет представление при обнаружении изменений. Поэтому вычисления в шаблоне должны быть быстрыми и не менять состояние. Сортировка исходного массива прямо из вызываемого шаблоном метода способна незаметно менять данные при отрисовке. Лучше заранее подготовить значение или позже использовать `computed`.

## Как узнать standalone в PL

По вашей проверке PL2.2, PL2.1 и PL1.26 запускаются через `bootstrapApplication` и используют standalone-компоненты. В Angular 19 и новее `standalone` по умолчанию равен `true`; его отсутствие в декораторе не означает NgModule. В учебном примере ниже он указан явно для наглядности. Собственный standalone-компонент также может импортировать NgModule библиотеки — это не превращает всё приложение в модульную архитектуру.

В рамках времени разбора примера потратьте 5 минут на один компонент PL: найдите `@Component`, `templateUrl` и `imports`, затем один `(click)` в его шаблоне. Через переход к определению выясните, чей компонент используется: собственный, Material или Bootstrap-обёртка. Пока не требуется разбираться во всей карте или дереве оборудования. Результат: вы можете показать, где задаётся доступность компонента в шаблоне, и отличить её от TypeScript-импорта.

## Разобранная демонстрация

Полный файл: `practice/angular-labs/src/demos/w3-01.ts`. Из корня запустите `npm.cmd run practice:labs` и откройте `http://127.0.0.1:4304/w3-01`. Подключение уже сделано в `practice/angular-labs/src/app.ts`; вручную копировать код в трекер не требуется. Ожидаются две книги, после нажатия «Сети» — выбранный ID `b2`. Это отдельная библиотека книг, а не решение задания.

```ts
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-library-demo',
  standalone: true,
  template: `
    <h2>Книги</h2>
    @if (books.length) {
      <ul>
        @for (book of books; track book.id) {
          <li>
            <button type="button" (click)="selected.set(book.id)">
              {{ book.name }}
            </button>
          </li>
        }
      </ul>
    } @else { <p>Книг пока нет</p> }
    <p>Выбрано: {{ selected() ?? 'ничего' }}</p>
  `,
})
export class LibraryDemo {
  books = [{ id: 'b1', name: 'Алгоритмы' }, { id: 'b2', name: 'Сети' }];
  selected = signal<string | null>(null);
}
```

До нажатия видно «ничего», после второй кнопки — `b2`. Signal пока считайте ячейкой с явным чтением через `()` и записью через `set`; механизм разберём [отдельно](/lessons/w3-03). Замените `books` пустым массивом: список исчезнет, появится объяснение. Условный блок создаёт и удаляет DOM, а не просто прячет его цветом.

`track book.id` сообщает, как сопоставлять элементы списка между обновлениями. Устойчивый ID переживает сортировку, изменение названия и вставку в начало. Индекс обозначает позицию, поэтому плохо подходит для изменяемого списка: та же позиция завтра принадлежит другой записи. Ключи должны быть уникальными. Это особенно заметно у строк с вводом и фокусом.

## Мост от Java

Декоратор напоминает аннотацию, но компонент не является Spring controller. Он выполняется в браузере и управляет частью DOM. Поле класса не становится HTTP-параметром; `imports` компонента не является Java import и не запускает сетевой обмен. Нажатие вызывает обычный метод TypeScript, а не отдельный серверный запрос, пока вы явно его не добавите.

## Проверка понимания

1. Чем отличаются `disabled="false"` и `[disabled]="false"`?
2. Почему одного TypeScript import недостаточно для дочернего компонента?
3. Что произойдёт с экземплярами строк при смене ключей?
4. Почему шаблон не должен менять исходный массив?

Новая вариация: покажите отдельную подпись, если выбранная запись исчезла после фильтрации. Решите, должен ли выбор сохраняться, и объясните решение.

## Критерии ручной проверки

Список, выбор и пустое состояние наблюдаются в браузере; ключ основан на ID; ввод с угловыми скобками остаётся текстом; вы можете показать файл данных и обработчик без подсказки. Отметьте отдельно чтение, выполнение и способность повторить.
