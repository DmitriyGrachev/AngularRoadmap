# middle-03 — Сохранить инварианты выбора в Signals store

## Механизм

Выбранный объект не должен храниться независимо от списка: после замены списка это был бы устаревший snapshot. Храните ID, вычисляйте selected, а команды store поддерживают инварианты. Отсутствие реального изменения должно сохранять ссылку контейнера.

### Контракт API

`createSelectionStore(items)` возвращает настоящие Angular Signals `items`, `selectedId`, `selected` и методы `select(id|null)`, `replace(items)`, `rename(id,title)`. Входные записи имеют уникальные id и title. Изначально selectedId и selected равны null. select(null) сбрасывает выбор; известный ID выбирается, неизвестный игнорируется. selected — текущий объект из items либо null. replace устанавливает новый список: сохраняет ID, если запись осталась, иначе сбрасывает выбор. rename создаёт новый массив и новый объект только для изменённой записи; остальные объекты и все дополнительные поля сохраняются. Для отсутствующего ID или прежнего title ссылка items() остаётся прежней. Входные массивы и записи не мутируют. Допустимы только signal/computed из установленного @angular/core, имитация функции-геттера не подходит.

### Пример и новая проверка

Выберите b, затем замените список на [{id:"b",title:"New"}]: selected ссылается на новый b. Удаление b сбрасывает выбор. Новый пример: переименуйте a при выбранном a; selected сразу показывает новое title.

## Критерии

- Публичные значения — реальные Signals; выбранная запись относится к текущему списку.
- replace не оставляет ID исчезнувшей записи.
- rename сохраняет неизменённые ссылки и не создаёт обновление для no-op.

## Подсказки по порядку

1. selected удобно выразить через computed и find.
2. Проверяйте существование ID до select; проверяйте его снова после replace.
3. До map проверьте, действительно ли title изменился.

## После своей попытки
