# Получить зависимость из текущего Angular Injector

Урок w3-04, около 30 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

Дочерний injector может переопределять токен. Глобальное создание repository внутри функции обходит локальную настройку и ломает тестируемость. inject вызывается в injection context: захватите зависимость при выполнении фабрики, не внутри позднего обработчика после await. Это напоминает Spring DI, но Angular имеет иерархию injector и явное ограничение контекста inject().

### Контракт API

Экспортируйте ISSUE_REPOSITORY=new InjectionToken(...) и createIssueReader(). Функция вызывается Angular как useFactory и получает repository через inject(ISSUE_REPOSITORY). repository.list():Promise<Issue[]> предоставляется снаружи. Верните объект с async listOpen(): при каждом вызове он загружает свежий список, возвращает только OPEN по порядку и распространяет ошибку Promise. Не храните repository глобально и не создавайте свой injector.

### Пример и новая проверка

Родитель видит общий repository, дочерний override — локальный. Новый пример: createIssueReader() вне injection context должен дать стандартную ошибку Angular.

## Условия приёмки

- Используются настоящий InjectionToken и текущая область DI.
- listOpen фильтрует свежий результат и сохраняет порядок.
- Ошибка зависимости распространяется; injector кеширует экземпляр.
