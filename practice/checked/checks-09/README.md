# Создать Reactive Form с предсказуемым reset

Урок w5-01, около 40 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

Reactive Forms хранит значения и валидность в controls. nonNullable влияет на reset: он возвращает начальное значение вместо null. Nullable assignee должен очищаться в null. Валидатор возвращает null при успехе и объект ошибки при нарушении. Это не Java Bean Validation: Angular запускает валидатор при изменении control, включая программное setValue.

### Контракт API

createIssueForm(initial?) возвращает настоящий FormGroup с title,priority,assignee. Defaults: "", "NORMAL", null. title/priority — nonNullable, initial задаёт их defaultValue. assignee nullable, после reset становится null даже если initial содержал имя. title валиден при trimmed длине 3..80 включительно; priority — LOW/NORMAL/HIGH. Валидатор не меняет введённый текст. initial содержит все три поля. Используйте @angular/forms.

### Пример и новая проверка

title="  abc  " валиден и остаётся с пробелами, " x " невалиден. Новый пример: initial с LOW и исполнителем после reset сохраняет LOW, но очищает исполнителя.

### Работа

Из корня проекта выполните `npm.cmd run learn -- check checks-09`. Редактируйте только `practice/checked/checks-09/solution.mjs`. Сначала запишите прогноз или собственную попытку в тренажёре. Отчёт сохраняется в practice/reports и не отмечает урок освоенным автоматически.

## Условия приёмки

- Форма — FormGroup с тремя controls и нужными defaults.
- Проверяются trimmed границы title и закрытый список priority.
- reset возвращает начальные title/priority и assignee:null.

## Проверка

1. Запустите исходный вариант и прочитайте конкретные провалы.

`starter.mjs` — сохранённый исходный образец для проверки платформы. Работайте в `solution.mjs`: решённое упражнение не должно ломать общие тесты курса.
