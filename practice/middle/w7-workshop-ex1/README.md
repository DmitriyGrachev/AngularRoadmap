# Сравнительная сводка с ограниченными чтениями

Ручное задание к уроку [w7-workshop](../../../content/lessons/w7-workshop.md). Выбрать до восьми заявок и загрузить детали максимум тремя активными чтениями, сохранив порядок и частичный результат.

## Где работать

Реализация находится в вашей версии `practice/issue-tracker`: src/app/models.ts, issue.service.ts и компоненты/проверки вашей сводки. Эта папка задания хранит только условия и `notes.md` с доказательствами. Наличие заполненных заметок само по себе не подтверждает работу функции. Не заменяйте свои исходники авторским решением; сохраните предыдущие выполненные изменения.

```text
npm.cmd run practice:api
npm.cmd run practice:angular
npm.cmd run practice:test -- --watch=false
```

Адрес: http://127.0.0.1:4302. Нужен ваш трекер после недель 3–6 с реализованным HTTP-сервисом; исходный starter содержит локальные данные. Java API запускается отдельно. Проверьте реальный GET детали в Network до начала работы.

## Требования

1. Пустой выбор не запускается; повторные ID обрабатываются по записанной политике.
2. Каждая строка различает ожидание, загрузку, успех и ошибку; порядок совпадает с выбором.
3. Ошибка строки не останавливает остальные; повтор читает только эту строку.
4. Повторный запуск не создаёт второй активный пакет поверх первого. Старый пакет не меняет новый экран.
5. Ответы проверяются на внешней границе; клавиатурный повтор и понятный прогресс доступны.

## Проверка на новых данных

- Пять ID, второй отвечает раньше первого.
- Неизвестный ID среди существующих.
- Повтор ID и повтор одной ошибочной строки.
- Закрытие и новый пакет до завершения старого.

До кода запишите ожидаемое поведение, затем реализуйте и сравните результат. Если временные свойства проверяются тестом, управляйте завершением операций вручную; случайные задержки не доказывают отсутствие гонки. Baseline-тесты не являются оценкой новой функции.

## Что сохранить в notes.md

Таблица активных чтений, управляемый тест ограничения, тест старого пакета, пример частичного отказа и ручная проверка узкого экрана. Укажите команды и фактический результат, а также ограничения. Не копируйте служебные исходники и реальные данные работодателя.

## Рубрика

По каждому требованию отметьте «самостоятельно», «с подсказкой» либо «нужна повторная попытка» и приведите наблюдаемое доказательство. Обязательные свойства нельзя компенсировать красивым интерфейсом или количеством тестов. Полные критерии и три последовательные подсказки находятся в уроке. Для этой задачи автоматического выставления оценки через `learn check` нет; после собственной попытки выполните ручную проверку и отметку в платформе.
