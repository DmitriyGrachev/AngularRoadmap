# Строгие типы и проверка DTO на границе

180 минут: 40 на механизм, 30 на разбор, 80 на реализацию и 30 на новые данные. Предыдущий шаг — [ограничение параллелизма](/lessons/w7-01). Результат: вы отличаете известный компилятору тип от проверенного внешнего значения и проектируете явную границу декодирования.

## JSON не становится моделью от generic

Метод `http.get<Issue[]>` сообщает TypeScript, какую форму ответа ожидает программист. Angular не проверяет каждый полученный элемент на соответствие интерфейсу. Сервер может вернуть null, HTML от прокси, неизвестное поле статуса или объект без title. Приведение `as Issue[]` также не выполняет проверку во время исполнения. Оно изменяет знание компилятора, а не данные. Такая ошибка особенно неприятна, когда экран частично работает и падает только при редком ответе.

Значение на внешней границе удобно принимать как unknown. Чтобы прочитать поле, код обязан сузить тип: проверить объект, исключить null и массив, убедиться в типе свойства. В отличие от any, unknown сохраняет необходимость доказательства. Но даже корректный type predicate можно написать неверно; компилятор доверяет заявленному результату пользовательской функции. Поэтому runtime-условия и тесты decoder важнее красивой сигнатуры.

Разделяйте транспортную и внутреннюю модель. Строка даты JSON остаётся строкой после JSON.parse. Если код ожидает Date, требуется явное преобразование. Однако `new Date(value)` допускает форматы и нормализации, которые могут не подходить бизнес-контракту. Для точного календарного `YYYY-MM-DD` проверьте форму, календарную допустимость и обратное представление. Например, 2024-02-29 существует, 2023-02-29 — нет. Принять вторую дату как март означает незаметно изменить данные.

Дата без времени не равна timestamp события. Для текущего упражнения внутренний Date представляет полночь UTC и служит учебным контрактом. В продукте date-only часто разумнее хранить как отдельную календарную строку, иначе локальное форматирование может показать предыдущий день в другом часовом поясе. Выбор делается по смыслу данных. Урок не предлагает автоматически превращать все строки, похожие на дату, в Date.

## Что переносится из Java

Сравните decoder с Jackson-десериализацией и Bean Validation, но разделите роли. В Java DTO-класс существует во время исполнения; интерфейс TypeScript стирается. Jackson тоже не гарантирует все бизнес-инварианты без настройки и проверок. На клиенте дополнительно важно не потерять прежние данные и пользовательский ввод после некорректного ответа. Не нужно повторять весь backend domain validator: проверяйте свойства, без которых frontend не может безопасно работать.

Структурная типизация означает, что объект с нужными полями совместим с интерфейсом независимо от имени класса. Она удобна для небольших DTO, но не проверяет уникальность ID в коллекции и календарную корректность строки. Эти свойства относятся к данным целиком. После нормализации `' A '` и `'A'` становятся одинаковыми ID; проверка дублей до trim пропустит конфликт. Поэтому порядок действий decoder — часть контракта.

Выберите политику дополнительного поля. Для упражнения разрешено игнорировать незнакомые поля, создавая новый объект только с нужными свойствами. Это поддерживает совместимость при добавлении сервером необязательной информации. Недостающий обязательный title, напротив, делает ответ недопустимым. Не заменяйте его пустой строкой без согласованного требования: «исправленный» DTO может скрыть нарушение сервера и показать пользователю неверное состояние.

## Разобранный пример

Самостоятельный пример запускается Node без TypeScript-компилятора. Сохраните как `boundary-demo.mjs` в своей временной папке, выполните `node boundary-demo.mjs`:

```js
function readLabel(input) {
  if (typeof input !== 'object' || input === null || Array.isArray(input)) {
    return { ok: false, error: 'invalid-data' };
  }
  if (typeof input.label !== 'string' || input.label.trim() === '') {
    return { ok: false, error: 'invalid-data' };
  }
  return { ok: true, value: { label: input.label.trim() } };
}
const raw = { label: '  Сети  ', internalFlag: true };
console.log(JSON.stringify(readLabel(raw)));
console.log(JSON.stringify(readLabel({ label: 7 })));
console.log(raw.label === '  Сети  ');
```

Ожидаются `{"ok":true,"value":{"label":"Сети"}}`, `{"ok":false,"error":"invalid-data"}` и `true`. Последняя строка доказывает отсутствие изменения исходного объекта. Вариант `input.label.trim()` без проверки типа падает на числе; `String(input.label)` принимает число и тем самым молча расширяет контракт. Здесь обе альтернативы ошибочны по разным причинам.

В TypeScript результат удобно оформить discriminated union с полем ok. В ветке `if (result.ok)` доступны value и проверенная модель; в другой — error. Это заставляет вызывающий код принять решение. Флаг не заменяет обработку: если сервис выбрасывает всю информацию об ошибке и возвращает `[]`, UI путает поломанный ответ с пустым поиском. Проверка формата должна происходить в одном месте перед передачей данных в store или компонент.

## Практика в IDE — middle-02

В `practice/middle/middle-02/solution.mjs` реализуйте `decodeIssues(input)`. Полный контракт лежит рядом в README: на успехе `{ok:true,value:[{id,title,createdAt:Date}]}`, на отказе `{ok:false,error:'invalid-data'}`. Проверяется массив целиком; id и title — непустые строки после trim, createdAt — точная допустимая дата `YYYY-MM-DD`, ID уникальны после нормализации. Исходные объекты и массив не меняются. Частично правильная коллекция не выдаётся как успешная.

Команда: `npm.cmd run learn -- check middle-02`. Перед кодом составьте таблицу «вход / допустимость / нормализованное значение»: null, пустой массив, пустой title, дубликат после trim, високосная дата и дополнительное поле. Решите, когда можно создавать результат, а когда нужно прекратить обработку. Упражнение исполняется как JavaScript ради простой проверки runtime-поведения; для переноса в Angular добавьте unknown и типизированный результат, сохранив те же условия.

Наконец передайте замороженные входные объекты: корректный decoder не должен требовать их мутации.

## Критерии самопроверки

Обязательны отсутствие исключения на внешнем неизвестном значении, строгая проверка обязательных полей, календаря и дублей, сохранение входа. Самостоятельность подтверждается объяснением, почему generic HTTP-клиента не валидирует JSON, где проходит граница decoder и как UI различит пустой результат и нарушение контракта. Перенос на новое требование: добавьте в собственном черновике необязательное поле priority и письменно выберите политику неизвестного значения, не меняя установленный контракт автозадания.
