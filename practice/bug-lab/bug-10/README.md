# bug-10: Ответ пришёл, индикатор загрузки не исчез

Связанный урок: [w4-03](../../../content/lessons/w4-03.md). Около 35 минут; упражнение может заменить часть ручной практики урока.

Симптом: данные показаны, но loading остаётся true до закрытия экрана. Выполните node practice/bug-lab/bug-10/repro.mjs: HTTP выдаёт результат и завершается, triggers$ остаётся открытым. Исправьте createLoader. Затем проверьте смену запроса при ожидании: простое перемещение finalize может создать другую ошибку, выключая индикатор нового чтения.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-10/repro.mjs
npm.cmd run learn -- check bug-10
```

Сценарий работает без сайта, dev server и Java API с установленными зависимостями проекта. Исходный дефект намеренно завершает repro с AssertionError и ненулевым кодом. После исправления сценарий завершается успешно. Полная проверка создаёт отчёт версии 1 для учебного сайта.

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

createLoader(triggers$, request) возвращает { loading: Signal<boolean>, state$: Observable }. request(key) возвращает Observable массива. Здесь один потребитель state$; разделение нескольких потребителей рассматривает bug-03.

## Критерии результата

- loading включён во время запроса и выключен после его успеха или ошибки.
- Смена запроса отменяет старый и сохраняет loading: true для нового.
- ready/error сохраняют данные; отписка не оставляет loading включённым.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: A выполняется → старт B → отмена A → успех B. Проверяйте loading между событиями, а не только в конце. Затем повторите с ошибкой B и с отпиской во время ожидания.
