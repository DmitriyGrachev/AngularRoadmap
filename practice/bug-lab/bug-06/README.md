# bug-06: Ошибка сохранения уничтожила заполненную форму

Связанный урок: [w5-04](../../../content/lessons/w5-04.md). Около 30 минут; упражнение может заменить часть ручной практики урока.

Симптом: сервер ответил 503, сообщение осталось, но название и описание исчезли. Выполните node practice/bug-lab/bug-06/repro.mjs: настоящая заполненная FormGroup отправляется в save с отказом Promise. До правки getRawValue() возвращает пустые строки. Исправьте ветвление submit; выбранная политика запрещает редактирование на время ожидания.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-06/repro.mjs
npm.cmd run learn -- check bug-06
```

Сценарий работает без сайта, dev server и Java API с установленными зависимостями проекта. Исходный дефект намеренно завершает repro с AssertionError и ненулевым кодом. После исправления сценарий завершается успешно. Полная проверка создаёт отчёт версии 1 для учебного сайта.

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

createIssueForm({ title, description }) возвращает FormGroup. submit(form, save) возвращает Promise<{ ok, id?, message? }>; save(dto) — Promise<{ id }>. Вызывающая оболочка проверяет валидность до submit.

## Критерии результата

- Ошибка сохраняет значения и dirty; результат содержит ok: false и message.
- Во время save форма отключена, после любого исхода доступна.
- Повтор отправляет текущие значения; успех возвращает id и очищает форму.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: ошибка → исправление только title → успешный повтор. Убедитесь, что description сохранился и второй DTO содержит новый title. Объясните, какая дополнительная проверка нужна при редактировании во время ожидания.
