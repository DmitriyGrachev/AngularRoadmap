# bug-08: Медленный старый поиск перезаписывает новый

Связанный урок: [w4-04](../../../content/lessons/w4-04.md). Около 25 минут; упражнение может заменить часть ручной практики урока.

Симптом: ввод «с» → «сеть» сначала показывает сеть, потом результат снова относится к «с». Запустите node practice/bug-lab/bug-08/repro.mjs: второй ответ намеренно приходит раньше первого. До правки выдаются оба результата. Исправьте политику конкуренции searchLatest и сохраните пустую строку как запрос полного набора.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-08/repro.mjs
npm.cmd run learn -- check bug-08
```

Сценарий работает без сайта, dev server и Java API с установленными зависимостями проекта. Исходный дефект намеренно завершает repro с AssertionError и ненулевым кодом. После исправления сценарий завершается успешно. Полная проверка создаёт отчёт версии 1 для учебного сайта.

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

searchLatest(queries$, request) возвращает Observable результатов. request вызывается для каждого текста, включая "". Нормализация и debounce за границами изолированного дефекта.

## Критерии результата

- Старый ответ не выдаётся после нового текста.
- Новый текст отписывает предыдущий источник.
- Очистка строки запускает request и заменяет незавершённое чтение.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: ввод A → B → пустая строка, ответы B → пустая → A. В результате должен остаться только полный набор. Объясните, почему такую отмену нельзя автоматически переносить на POST.
