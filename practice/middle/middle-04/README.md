# middle-04 — Сделать фильтры устойчивыми к URL roundtrip

## Механизм

URL — сериализованный публичный ввод, доступный закладкам и ручному редактированию. Единая нормализация предотвращает разные трактовки состоянием компонента и маршрутом; изменение фильтра не должно стирать состояние соседних возможностей.

### Контракт API

Экспортируйте `readRoute(url)` и `writeRoute(url,filters)` для абсолютного URL. Filters: `{q:string,statuses:string[],page:number,pageSize:number,sort:string}`. Нормализованный q обрезан trim. statuses содержит только OPEN, IN_PROGRESS, DONE без повторений и именно в этом порядке; URL использует повторяемый ключ status. page — безопасное целое >=0; при чтении допустима только строка из десятичных цифр, иначе 0. pageSize — 10|25|50, по умолчанию 25; при чтении только точная строка "10"/"25"/"50". sort — title|updated, по умолчанию updated. Для одиночных URL-полей берётся первое значение. writeRoute нормализует runtime-поля: q не-строка→"", statuses не-массив→[], нечисловой/нецелый page→0, неподдерживаемые pageSize/sort→defaults. Удаляет все старые q/status/page/pageSize/sort, пишет нормализованные значения и пропускает defaults ("",[],0,25,updated). Возвращает строку URL, сохраняет origin/path/hash и все чужие параметры, включая повторения. Вход filters не мутирует.

### Пример и новая проверка

status=DONE&status=OPEN&status=DONE превращается в ["OPEN","DONE"]. q со знаком & проходит roundtrip без потери. Новый пример: tag=a&tag=b и #row-7 должны сохраниться после записи defaults.

## Критерии

- Плохие и повторные значения дают однозначное нормализованное состояние.
- write→read сохраняет нормализованные фильтры.
- Чужие query-параметры, pathname и hash сохраняются; defaults исчезают.

## Подсказки по порядку

1. Для повторяемого status нужен getAll; для одиночных полей — get.
2. Сначала удалите только пять собственных ключей, затем добавьте необходимые.
3. Общая нормализация для read/write уменьшает расхождения.
