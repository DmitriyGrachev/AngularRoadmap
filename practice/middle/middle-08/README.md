# middle-08 — Привязать серверные ошибки к актуальным строкам формы

## Механизм

Сервер проверяет snapshot, а пользователь продолжает редактировать и переставлять строки. Индекс массива ответа не является ID строки. Даже при совпавшей ревизии изменённое значение уже не то, которое отклонил сервер.

### Контракт API

`applyRowErrors(rows,response,snapshot,currentRevision)` → число применённых сообщений. rows — Angular FormArray групп с controls.id и controls.label (строки, ID уникальны). response=`{revision:number,errors:[{id:string,field:string,message:string}]}`; snapshot=`{revision:number,rows:[{id,label}]}` — неизменяемые данные отправленного запроса. Применяйте сообщения только если response.revision===snapshot.revision===currentRevision. Поддерживается только field==="label" и непустая после trim строка message; исходный текст сохраняется. Найдите актуальную строку по ID и строку snapshot по тому же ID. Если строка удалена/неизвестна или текущая label отличается от отправленной, пропустите. Иначе setErrors добавляет/заменяет ключ server, сохраняя все остальные errors. Значения, порядок, dirty/touched и ошибки других строк не меняются. Возвращайте число применённых сообщений (включая повторное сообщение для того же поля). Контейнеры response/snapshot предполагаются уже проверенными DTO.

### Пример и новая проверка

Ответ для a приходит после перемещения a с позиции 0 на 1: ошибка ставится на a. Новый пример: label(a) изменили после отправки — старую ошибку нельзя применять; неизменённая b всё ещё получает своё сообщение.

### Работа

Из корня проекта выполните `npm.cmd run learn -- check middle-08`. Редактируйте только `practice/middle/middle-08/solution.mjs`; starter остаётся исходной точкой. Сначала запишите прогноз или собственную попытку. JSON-отчёт появится в practice/reports; импорт отчёта не означает самостоятельное освоение урока.

## Критерии

- Сопоставление использует ID, а не индекс.
- Старые ревизии и ответы для нового пользовательского ввода игнорируются.
- Локальные errors сохраняются, значения формы не меняются.

## Подсказки по порядку

1. Сначала сравните три ревизии и верните 0 при несовпадении.
2. Найдите row и snapshot-row независимо от их позиции.
3. Сравните label и используйте {...field.errors,server:message}.

## После своей попытки

Общий номер запроса плюс сравнение значения — явный контракт этой лаборатории. Для приложения с параллельной отправкой разных секций выберите более точную модель field revisions; это отдельное расширение, не скрытое требование.
