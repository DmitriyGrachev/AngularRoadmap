# Учебный Angular-трекер

Запуск из корня: `npm.cmd run practice:angular`, затем `http://127.0.0.1:4302`.

Это самостоятельная заготовка с тремя локальными заявками, списком, деталями и простым вводом. Она работает без API. Изменяйте файлы `src/app/` по урокам недель 3–6; в них отмечены TODO. Поиск, работа с HTTP, полноценная форма, серверные ошибки и итоговые фильтры ещё не реализованы.

- `app.ts`, `app.html` — маршруты и каркас.
- `models.ts` — модель.
- `issue.service.ts` — локальные данные; позже HTTP.
- `issues-list.ts` — список; сюда добавляются фильтры, счётчик и страницы.
- `issue-detail.ts` — выбранная заявка.
- `issue-form.ts` — ввод; позже typed Reactive Forms, POST/PATCH и ошибки.

Для недель 4–6 отдельно запустите `npm.cmd run practice:api`; `/api` уже проксируется на `127.0.0.1:8080`. Отправка запросов — часть вашего задания, её нужно добавить в сервис.

Тесты Angular: `npm.cmd run practice:test` (или `npx.cmd ng test issue-tracker --watch=false`). Исходный `issue-detail.spec.ts` показывает TestBed и проверяет изменение ID/неизвестную запись. После реализации HTTP добавьте собственный `issue.service.spec.ts` с `provideHttpClient()`, `provideHttpClientTesting()`, `HttpTestingController`; готовые HTTP-тесты для авторского примера находятся отдельно. Команда без `--watch=false` запускает наблюдение за изменениями. Эти тесты проверяют ваш текущий код; по мере перехода от fixtures к API адаптируйте подготовку данных и добавляйте сценарии из уроков.

Законченный рабочий пример хранится отдельно в `author/solutions/issue-tracker` и запускается командой `npm.cmd run practice:demo` на порту 4303. Он предназначен для авторской проверки и разбора после попытки; запуск примера не меняет учебные файлы. Сайт курса также работает независимо от вашего проекта.
