# bug-11: HttpParams.set вызван, а фильтров в URL нет

Связанный урок: [w4-05](../../../content/lessons/w4-05.md). Около 25 минут; упражнение может заменить часть ручной практики урока.

Симптом: выбран статус и страница, а Network показывает запрос без query parameters. Выполните node practice/bug-lab/bug-11/repro.mjs: buildParams получает DONE, страницу 3 и строку с &. До правки toString() пуст. Исправьте построение настоящего HttpParams, сохранив trim строки и отсутствие фильтра для ALL.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-11/repro.mjs
npm.cmd run learn -- check bug-11
```

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

buildParams({ status, page, q }) возвращает Angular HttpParams. Вход содержит допустимый status и положительную целую page; q надо trim. ALL означает отсутствие status.

## Критерии результата

- page и выбранный status присутствуют в результате.
- q обрезан по краям и корректно кодирует кириллицу, пробелы и &.
- Для ALL и пустого q параметры status и q отсутствуют; разные вызовы независимы.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: DONE/page=9/q=ошибка, затем ALL/page=1/q=пробелы. Проверьте оба результата после второго вызова. Для «A&B + C» должен сохраниться один параметр q, а не появиться лишние параметры URL.
