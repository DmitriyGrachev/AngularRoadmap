# Читать незнакомый Angular-код по цепочке ответственности

120 минут. Результат: вы находите путь от URL до запроса и объясняете старый синтаксис без переписывания проекта. Нужны [компоненты](/lessons/w3-02), [DI](/lessons/w3-04), [Router](/lessons/w3-05), [HTTP](/lessons/w4-02).

## Ситуация и прогноз

По переданному разбору, PL2.2/PL2.1 запускаются через `bootstrapApplication` и используют standalone-компоненты. В PL1.26 основа тоже standalone, хотя версия Angular другая. Старые участки в данном случае — совместимость параметров URL и базовый класс с ручной отпиской, а не подтверждённая NgModule-архитектура. Если рядом встретятся `@Input`, `@Output` или constructor injection, знания курса остаются применимы: сначала ищите ответственность и поток данных. Предскажите, где искать причину неправильного названия: в маршруте, DTO, сервисе, поле компонента или выражении шаблона. Ответ зависит от места расхождения, а не от возраста синтаксиса.

## Начинайте с пользовательского сценария

Запишите URL и видимое действие. Найдите route, который выбирает страницу, затем класс компонента, его template/templateUrl и используемый сервис. В сервисе найдите метод, HTTP-адрес и тип ответа. Теперь можно пройти обратно от JSON к тексту. Это ограниченная карта конкретной функции, а не попытка прочитать весь репозиторий подряд.

Используйте поиск по имени маршрута, selector, подписи кнопки, методу API и части URL. Название файла может отличаться от курса: `issue-detail.component.ts` и `issue-detail.ts` оба могут содержать компонент. IDE go-to-definition полезен для импортов и наследования. Если слово встречается в десятках тестов, сузьте поиск до runtime-папки, но затем вернитесь к связанным проверкам.

Standalone-компонент импортирует зависимости своего шаблона непосредственно в metadata. Это основной путь чтения PL. Отсутствие явного `standalone: true` в Angular 19 и новее не делает компонент модульным: standalone используется по умолчанию. Импорт библиотечного NgModule в `imports` standalone-компонента также не меняет архитектуру приложения.

Стиль получения зависимостей также различается. `inject(Api)` в поле и constructor injection обычно выражают одну потребность получить Api из injector. Однако inject требует injection context; его нельзя бездумно перенести внутрь любого callback. Не меняйте весь стиль DI в рамках маленькой задачи, если текущий способ корректен и принят командой.

## Разобранная демонстрация

Полные компоненты: `practice/angular-labs/src/demos/w6-01.ts`; готовый родитель `InputStylesDemo` — в `practice/angular-labs/src/app.ts`. Команда `npm.cmd run practice:labs`, страница `http://127.0.0.1:4304/w6-01`. Обе кнопки «HTTP» показывают выбранный ID `b7`; Java API не нужен. Оба компонента имеют одинаковую внешнюю идею: получить название книги и сообщить выбранный ID.

```ts
import { Component, EventEmitter, Input, Output, input, output } from '@angular/core';

@Component({
  selector: 'modern-book', standalone: true,
  template: `<button type="button" (click)="selected.emit(id())">{{ title() }}</button>`,
})
export class ModernBook {
  id = input.required<string>();
  title = input.required<string>();
  selected = output<string>();
}

@Component({
  selector: 'decorator-book', standalone: true,
  template: `<button type="button" (click)="selected.emit(id)">{{ title }}</button>`,
})
export class DecoratorBook {
  @Input({ required: true }) id = '';
  @Input({ required: true }) title = '';
  @Output() selected = new EventEmitter<string>();
}
```

В готовом родителе imports уже перечисляет оба класса и передаёт одинаковые id/title/selected; сравните код. Ожидается одинаковый пользовательский результат. Но в классе modern-вход читается вызовом, decorator-вход — полем. Механическая замена `title` на `title()` во всём старом шаблоне сломает код. Вариация: удалите обязательный binding у одного использования и прочитайте сообщение компилятора, затем восстановите его.

Старые структурные директивы `*ngIf` и `*ngFor` могут встречаться рядом с новым `@if`/`@for`. Они тоже управляют создаваемыми представлениями, но требуют соответствующих imports и имеют другой синтаксис. Перед изменением проверьте конкретную версию Angular в package.json. Не копируйте синтаксис из документации другой версии без проверки поддержки.

Справочно, для чужого модульного проекта достаточно прочитать миниатюру: `@NgModule({ declarations: [LegacyPage], imports: [CommonModule], exports: [LegacyPage] })`, где `LegacyPage` — компонент с `standalone: false`. Это не описание PL и не требование внедрить модуль в трекер. При «unknown element» в PL сначала проверьте `imports` конкретного standalone-компонента и экспорт используемой библиотечной зависимости.

## Из какой библиотеки пришёл элемент PL

По вашему разбору PL2.2, интерфейс сочетает Angular Material/CDK, Bootstrap 5.3.8, две разные Angular-библиотеки `@ng-bootstrap/ng-bootstrap` 20.0.0 и `ngx-bootstrap` 21.2.1, собственные компоненты и ECharts/ngx-echarts. PrimeNG не найден. Это карта существующих решений, а не список пакетов для установки в учебный проект.

| Наблюдение в коде | Что установить до изменения |
| --- | --- |
| Import из `@angular/material/...` или `@angular/cdk/...` | Какой компонент или инструмент подключён; кто отвечает за меню, фокус, drag-and-drop или уведомление |
| Bootstrap-классы в HTML | Кто задаёт оформление и кто управляет поведением; класс `modal` сам по себе не определяет Angular API |
| Import из `@ng-bootstrap/ng-bootstrap` | Контракт именно ng-bootstrap для этого элемента, входы, выходы и закрытие |
| Import из `ngx-bootstrap/...` | Контракт именно ngx-bootstrap; похожее название не делает его API взаимозаменяемым с ng-bootstrap |
| Собственный selector, например таблицы | Класс компонента, типы данных, inputs/outputs, шаблон строки; наличие внешней библиотеки внутри проверяется по исходнику |
| Import из `ngx-echarts` | Граница Angular-компонента и опций ECharts; сначала владелец данных, затем настройка графика |

Для найденного `SimpleTableComponent` сначала прочитайте его публичный контракт. Не предполагайте по внешнему виду, что это `MatTable`, и не подменяйте таблицу примером из документации Material. При задаче «добавить столбец» выясните, таблица получает готовые колонки или шаблон, кто формирует строку и кто обрабатывает событие выбора. Новая библиотека обычно не нужна, если в проекте уже есть принятый компонент для того же сценария.

У смешанного интерфейса проверяйте не только внешний вид: после закрытия модального окна фокус должен возвращаться в понятное место, обработчик не должен оставаться активным, а событие сохранения должно срабатывать только один раз. Конкретный API берите из установленного пакета и соседнего рабочего примера. Наличие одной зависимости в package.json ещё не доказывает её использование на выбранной странице.

## Мост от Java

Поиск route → component → service похож на controller → service → client в Java. Но Angular template содержит выполняемые выражения и собственные зависимости. Вложенный UI-компонент — не отдельный REST endpoint. NgModule также не равен Java module-info: он описывает Angular compilation/injection context, а TypeScript ES imports продолжают существовать отдельно.

Полезная карта показывает, кто читает и кто меняет данные, где выполняется запрос и какие состояния отображаются. Она не должна превращаться в диаграмму каждого класса. Если после пятнадцати минут чтения вы не можете назвать владельца title, остановитесь и проследите одно значение debugger, вместо дальнейшего пассивного просмотра файлов.

### Разбор PL — 20 минут внутри урока

Вместо дополнительной вариации подписи статуса выберите одну небольшую рабочую страницу. За пять минут найдите путь route → component → template. За следующие десять минут проследите один табличный элемент и одно действие: это собственный компонент, Material/CDK, ng-bootstrap или ngx-bootstrap? Запишите только имена слоёв и ответственность: откуда приходят строки, кто владеет выбранным значением, какой выход сообщает о действии и где находится cleanup. Если выбранного вида элемента на странице нет, отметьте отсутствие; искать все библиотеки сразу не требуется. Последние пять минут объясните, какой минимальный участок затронуло бы добавление столбца или обработчика. Служебные данные и исходники в отчёт курса не копируйте. Общая длительность урока остаётся 120 минут.

## Критерии ручной проверки

Карта подтверждается реальным запросом; ответственность каждого звена объяснена; оба варианта inputs/outputs прочитаны; область регистрации найдена. Для выбранного элемента PL установлен реальный источник API; вы различаете собственную таблицу, Material/CDK и два Bootstrap-wrapper, не предполагая их взаимозаменяемость. Маленькое изменение локализуется без случайного редактирования DTO и миграции архитектуры.
