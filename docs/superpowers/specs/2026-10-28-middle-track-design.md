# Второй этап: frontend для Middle Fullstack

## Задача и ограничения

Пользователь уверенно работает со Spring Boot, JPA, SQL и тестами; главный пробел — frontend. Он просит расширить действующий курс теорией и практикой для самостоятельной работы Middle Fullstack Angular + Java. Нагрузка остаётся 15–20 часов в неделю. Целевой рабочий стек PL2: Angular 21.2.18, standalone, собственные Signals + RxJS сервисы, Material/CDK, Bootstrap-обёртки и собственные компоненты. Учебный runtime остаётся Angular 22.2.3 / TS 6.0.3; совместимость всей платформы с 21 не обещается.

## Подход

Сохраняем первые 36 уроков / 90 часов и добавляем последовательный второй этап недель 7–12: 24 урока / 90 часов. Каждая новая неделя содержит три занятия по 180 минут и практикум на 360 минут. Итого 60 уроков, 180 обязательных часов плюс резерв. Это план учебной нагрузки, а не обещание трудоустройства или присвоения Middle по завершении чтения.

Рассмотрены расширение первых шести недель (перегружает старт), отдельная новая платформа (дублирует прогресс и инструменты), продолжение в существующем каталоге. Выбрано продолжение как реализация явного запроса расширить текущий курс. Декомпозиция и длительности — решение исполнителя с учётом указанного опыта.

## Содержание и практические контракты

| Неделя | Занятия 01 / 02 / 03 / workshop | Проверяемые задания |
|---|---|---|
| 7 | Асинхронность и ограничение параллелизма / типы и проверка DTO / браузер, CSS и доступность / устойчивый клиентский модуль | middle-01: bounded concurrency; middle-02: DTO boundary |
| 8 | Signals store и инварианты / Router и URL как состояние / границы компонентов и DI / архитектура feature | middle-03: store; middle-04: URL roundtrip |
| 9 | RxJS cache и время жизни / очереди записи / отмена, ошибки и события / экран с конкурирующими запросами | middle-05: cache invalidation; middle-06: serialized writes |
| 10 | Сложные typed forms / серверные ошибки динамических строк / UI-компоненты, CVA, Material/CDK и фокус / редактор с доступной валидацией | middle-07: nested forms; middle-08: errors by stable ID |
| 11 | API и Problem Details / optimistic concurrency / безопасность browser ↔ Java / изменение через весь стек | middle-09: error mapping; middle-10: versioned optimistic state |
| 12 | Поведенческие тесты и дефектные реализации / профилирование и большие таблицы / доставка, наблюдаемость и инцидент / самостоятельная задача и защита | middle-11: student-written contract tests; middle-12: virtual window |

12 автоматических упражнений имеют неизменяемый starter, редактируемое решение, отдельный авторский ответ, проверку граничных случаев и JSON-отчёт существующего runner. Их имена middle-01…middle-12 связаны с первыми двумя занятиями каждой недели. Ещё 12 ручных заданий (03 и workshop) имеют отдельные папки practice/middle/wN-03-ex1 и wN-workshop-ex1, условия, артефакт learner notes и критерии; они дорабатывают существующие учебные приложения. Рабочие PL-исходники не копируются и не меняются.

Материал каждого занятия: механизм и границы, Java-аналогия, разбор примера с ожидаемым поведением, самостоятельная задача, три подсказки, проверка на новых данных, критерии и первичные источники. Backend-основы не повторяются; интеграционные задания используют Java-компетенции пользователя. Если лаборатория не моделирует HTTP, auth, DB или реальную конкурентную запись, это явно указано, а проверка соответствующего свойства переносится в полноценный интеграционный практикум.

## Платформа и прогресс

Сохраняем schemaVersion=1, ID старых уроков и упражнений, ключи localStorage и оба формата экспорта. Новый контент включается в штатные уроки и тренажёр. Числа недель/уроков/часов и материалов вычисляются из каталога. На роадмапе видны базовый и продвинутый этапы, старт второго этапа и требования к самостоятельной защите. Успешный тест не присваивает профессиональный уровень.

## Готовность и доказательства

Четыре вида свидетельств: работающая новая функция, воспроизводимый дефект и исправление, изменение frontend + Java API с контрактом, устная защита компромиссов и тестов. Итоговая рубрика различает выполнение с подсказками, самостоятельное решение и перенос на новое требование; безопасность, сохранность пользовательского ввода и корректность записи — обязательные условия.

Проверка реализации: content validator, автоматические starter-fail/author-pass и отрицательные варианты, импорт прежнего прогресса в расширенный каталог, сборка, E2E перехода к неделе 12/новому заданию/импорта отчёта и сохранения старых отметок, desktop/mobile без ошибок. Никаких новых зависимостей и миграции учебной версии Angular в этом расширении.
