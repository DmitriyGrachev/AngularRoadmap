# Как браузер показывает страницу

**Результат:** вы собираете осмысленную карточку заявки и показываете, как HTML-файл превращается в дерево элементов в браузере. Занятие — 120 минут: 10 на диагностику, 30 на механизм, 20 на пример, 45 на свою карточку, 15 на проверку.

## Рабочая ситуация и исходные знания

Коллега просит добавить на страницу название заявки, описание и кнопку. Начать нужно с того, что именно открывает браузер. Опыт Java здесь полезен для чтения файлов и выполнения инструкций; знание HTML пока не требуется. Откройте папку проекта в IDE и терминал в её корне. Команды курса выполняются оттуда, если явно не указан другой каталог. В PowerShell при блокировке `npm.ps1` используйте `npm.cmd` вместо `npm`.

За первые десять минут запишите своими словами: где работает Java backend, где выполняется код страницы, чем отличается ссылка от кнопки. Если ответ неизвестен, оставьте вопрос. Это отправная точка, а не экзамен по установке среды. Среда уже подготовлена; при ошибке запуска сначала проверьте корневой README.

## Сначала прогноз

Прочитайте фрагмент, не открывая браузер:

```html
<h1>Заявки</h1>
<article>
  <h2>Не приходит письмо</h2>
  <p>Статус: <strong>OPEN</strong></p>
  <button type="button">В работу</button>
</article>
```

Сколько здесь заголовков? Изменится ли статус от одного нажатия кнопки? Почему `OPEN` визуально выделено? Прогноз нужен до запуска: иначе легко принять узнавание готового результата за понимание.

## Как страница появляется в браузере

Браузер — программа на компьютере пользователя. Сервер — программа, которая принимает запросы и возвращает ответы. При открытии HTTP-адреса браузер запрашивает ресурс по URL, то есть адресу. Ответ содержит статус и тело, например текст HTML. Учебный сервер на `localhost` работает на вашем компьютере; это не отменяет разделение клиента и сервера. Сейчас он отдаёт файлы, позднее Java API будет отдавать данные заявок.

HTML — язык разметки. Он описывает смысл и вложенность содержимого. Элемент обычно имеет открывающий тег, содержимое и закрывающий тег: `<p>Текст</p>`. Атрибут в открывающем теге уточняет элемент: `type="button"` задаёт тип кнопки. Одни элементы, например `meta` и `input`, не содержат дочернего текста и не требуют закрывающего тега.

В начале документа `<!doctype html>` включает стандартный режим отображения. Корневой `html` объединяет документ, `head` содержит служебные сведения, `body` — видимое содержимое. `meta charset="UTF-8"` позволяет правильно прочитать русские буквы; `title` задаёт название вкладки. Атрибут `lang="ru"` помогает средствам чтения с экрана произносить текст. `meta viewport` нужен, чтобы мобильный экран не изображал уменьшенную широкую страницу.

Браузер разбирает текст и строит DOM — Document Object Model, дерево объектов документа. В дереве `article` становится родителем заголовка, абзаца и кнопки. DOM существует в памяти и доступен инструментам браузера и JavaScript. Исходный файл и DOM связаны, но не обязаны в каждый момент быть одинаковыми: скрипт может изменить текст, браузер может исправить неверную вложенность. Исправление через Elements временно меняет DOM; после перезагрузки браузер снова читает файл.

HTML несёт смысл. `h1` обозначает главный заголовок страницы, `h2` — заголовок раздела, `p` — абзац, `article` — самостоятельный фрагмент. Уровни заголовков выражают структуру, а не желаемый размер букв. Ссылка `a` с `href` ведёт к адресу; кнопка запускает действие. Пользователь может активировать настоящую кнопку клавиатурой, а браузер уже знает её роль. Окрашенный `div` таких свойств сам по себе не получает.

## Мост от Java

DOM можно представить как дерево объектов с родителями и детьми. Это помогает понять обход и изменение узлов. Но HTML не является Java-классом, а тег не вызывает backend-метод. Для кнопки сначала существует элемент интерфейса; поведение добавляется отдельно. Нажатие без обработчика не меняет нашу заявку. Серверный Java-код и будущий JavaScript в браузере выполняются в разных средах и общаются через запросы.

## Разобранный пример

Запустите `npm.cmd run practice:web` и откройте [пример HTML](http://127.0.0.1:4301/foundations/web-basics/examples/html.html). Его исходник — `practice/foundations/web-basics/examples/html.html`. Ожидается заголовок «Заявки команды», карточка «Не приходит письмо», выделенный `OPEN`, ссылка и кнопка. Ссылка перемещает к разделу «Описание»; кнопка пока ничего не меняет. Это корректное наблюдение, а не неисправность JavaScript.

Откройте DevTools клавишей F12 и вкладку Elements. Выберите `strong`, измените `OPEN` на `DONE` прямо в дереве. На странице появится новый текст. Перезагрузите страницу: вернётся `OPEN`, потому что файл не менялся. Теперь измените текст в IDE, сохраните и обновите вкладку. Такой цикл связывает исходник, DOM и наблюдаемый результат. Типичная ошибка — исправлять только Elements и ожидать сохранения в проекте.

## Критерии

- Есть один главный заголовок и осмысленная вложенность карточки; русские символы отображаются правильно.
- Ссылка ведёт к существующему разделу; кнопка является элементом `button` с понятной подписью.
- После перезагрузки изменения сохраняются; вы показываете соответствующий узел в Elements.
- Вы объясняете различие файла, DOM и серверного ответа без указания готовой строки.
