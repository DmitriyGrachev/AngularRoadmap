# Практикум: небольшой список заявок

**Результат:** вы соединяете HTML, CSS и JavaScript в одну понятную страницу. Нужно пройти [карточку](/lessons/w1-01), [оформление](/lessons/w1-02), [события](/lessons/w1-03), [массивы](/lessons/w1-04) и [форму](/lessons/w1-05). Практикум занимает 300 минут и может быть разделён на несколько подходов.

## Ситуация и план времени

Команде нужен локальный прототип: видеть заявки, фильтровать по статусу и завершать выбранную заявку. Сервер и сохранение после перезагрузки пока не требуются. Вы получаете модель данных и пустые места интерфейса, но последовательность правок выбираете сами.

Первые 180 минут — связать список, фильтр и действия. Следующие 60 — самостоятельно добавить приоритет и исправить обнаруженный дефект. Последние 60 — пройти сценарии и объяснить механизм. Если основа не работает, резерв тратится на неё; дополнительные украшения не являются условием завершения.

## Прогноз и механизм

Перед кодом запишите: если при фильтре OPEN завершить одну из двух открытых заявок, сколько останется? Должна ли она вернуться при выборе ALL? Ответ: одна и да. Данные и видимое подмножество различаются. Изменение статуса относится к исходной модели, фильтр вычисляет представление из текущей модели, render отображает его. Если хранить только отфильтрованный массив как новый источник истины, возврат ALL потеряет элементы.

Java-разработчику полезна аналогия с моделью и представлением, но здесь они живут в одной вкладке. Изменение локального объекта не сохраняет сущность в базе. Реальные данные после обновления будут снова взяты из файла. Расскажите это во время демонстрации, чтобы не спутать прототип с серверной системой.

## Доступный разобранный ориентир

Повторно откройте [пример формы](http://127.0.0.1:4301/foundations/web-basics/examples/forms.html). Для двух исходных заявок последовательность ALL → OPEN → DONE → ALL даёт «Письмо, Кнопка» → «Письмо» → «Кнопка» → обе. Это пример механизма фильтра, а не решение практикума с карточками и изменением статуса. Теперь мысленно добавьте завершение первой заявки: при OPEN она должна исчезнуть, при DONE — появиться.

## Практика в IDE

Упражнение `w1-workshop-ex1`, каталог `practice/foundations/web-basics/w1-workshop-ex1`. Редактируйте `index.html`, `styles.css`, `main.js`. Запуск — `npm.cmd run practice:web`; страница — [мой трекер](http://127.0.0.1:4301/foundations/web-basics/w1-workshop-ex1/index.html).

Покажите три исходные заявки отдельными карточками с названием и статусом. Добавьте доступный фильтр ALL/OPEN/DONE, понятное пустое состояние и действие завершения конкретной заявки по id. Уже завершённая заявка не должна снова предлагать такое действие. Выводите строки через textContent; если создаёте элементы динамически, `document.createElement('p')` создаёт узел, а `container.append(element)` добавляет его в контейнер. Это позволяет не собирать HTML из пользовательских строк.

Самостоятельное расширение: отобразите приоритет HIGH/MEDIUM/LOW понятными словами и не только цветом. Затем проверьте дефект: после нескольких переключений ALL должен возвращать все три карточки. Если дефект не возник, намеренно воспроизведите его в отдельной временной копии, фильтруя уже отфильтрованные данные, и объясните причину.

## Критерии

- Сценарии: первая загрузка — три заявки; OPEN — две; завершение одной — одна; ALL — снова три.
- DONE показывает завершённые, отсутствие совпадений имеет текст, данные не теряются при фильтрации.
- Приоритет понятен по тексту; Tab и Enter доступны; при 375 и 1280px нет обрезанных действий.
- Вы объясняете путь данные → событие → изменение → отображение и самостоятельно меняете поле одной карточки.
- Результат оценивается вручную: для каждого пункта укажите «самостоятельно», «с подсказкой» или «нужна повторная попытка».

## Проверка понимания

1. Почему индекс видимого списка ненадёжен как идентификатор?
2. Что теряется после перезагрузки и почему?
3. Где вычисляется фильтр и где отображается результат?
4. Как проверить приоритет без опоры на цвет?

Новая вариация: добавьте в данные четвёртую заявку со статусом IN_PROGRESS и сформулируйте изменение фильтра. Повторите контрольную точку без указания конкретных строк. Если не получается, выберите один пробел и вернитесь к соответствующему уроку на 15 минут.
