# Объединить страницы без дублей и потери обновлений

Урок w4-05, около 30 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

Догружаемая страница может повторять известную заявку. Конкатенация создаёт дубль, фильтрация всех повторов теряет свежие данные. Индекс Map позволяет первой встрече задать позицию, последней — содержимое. Это похоже на Java LinkedHashMap. В отличие от {}, Map безопасен для произвольных строковых ключей вроде __proto__.

### Контракт API

mergePage(previous,incoming) возвращает новый массив уникальных заявок по строковому id. Порядок — первое появление при обходе previous, затем incoming. Значение — последний объект с этим id, включая повторы внутри одной страницы. Не объединяйте поля версий: используйте целиком последний объект. Вход не мутирует и может быть frozen. Допустимы любые строковые id, включая __proto__ и constructor.

### Пример и новая проверка

[A(old),B] + [B(new),C(first),C(last)] → [A(old),B(new),C(last)]. Новый пример: previous тоже содержит повтор A — сохраните первую позицию и последнюю версию.

## Условия приёмки

- Один объект на id; последняя версия побеждает.
- Позиция соответствует первому появлению.
- Нет мутаций; пустые страницы и специальные id поддерживаются.
