# Пережить ошибку чтения и повторить тот же id

Урок w4-03, около 35 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

Ошибка завершает Observable. catchError вокруг всего ids$ заменяет всю цепочку, поэтому следующие действия могут перестать работать. Обрабатывайте ожидаемую ошибку внутри switchMap, на уровне одного запроса. Это похоже на разницу между try/catch вокруг одного Java-вызова и вокруг всего цикла.

### Контракт API

loadIssueState(ids$,load) возвращает Observable. Для каждого id без debounce и distinct выдайте {kind:"loading",id}; успех load(id) → {kind:"ready",id,issue}; Error → {kind:"error",id,message:error.message}; неизвестная форма ошибки → message:"Ошибка загрузки". Новый id отменяет прежнее чтение через switchMap. После отказа повтор того же id запускает новый load. Ошибки не выходят через error-канал.

### Пример и новая проверка

X → offline → X → success даёт loading,error,loading,ready. Новый пример: медленное A и быстрое B оставляют только результат B.

## Условия приёмки

- Ошибка превращается в состояние, ids$ остаётся живым.
- Повтор того же id после отказа вызывает новый load.
- Новое id отменяет старую подписку.
