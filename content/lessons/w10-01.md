# Вложенные typed forms: структура, инварианты и DTO

180 минут: 40 на механизм, 35 на пример, 80 на самостоятельную реализацию и 25 на граничные случаи. Нужен [практикум конкурирующих запросов](/lessons/w9-workshop). Результат — настоящая Angular-форма с вложенной группой и массивом, которую нельзя случайно заполнить неправильными типами.

Здесь и далее используются подходы рабочего Angular 21: standalone, typed Reactive Forms, Signals и RxJS. Учебный runtime остаётся Angular 22; новые API только из 22 не требуются. Проверки в курсе не означают сборку всей платформы под Angular 21.

## Форма — отдельная модель редактирования

DTO описывает данные обмена, FormGroup — граф контролов. Кроме value у контролов есть validity, disabled, dirty, touched и события. Поэтому `FormGroup<EditorInput>` обычно неверен: generic FormGroup ожидает карту контролов, а не обычных значений. У формы и DTO часто одинаковые названия полей, но разные обязанности. Преобразование между ними должно быть явным, особенно при optional, null и отключённых полях.

Typed Reactive Forms дают проверку TypeScript при обращении к контролам и установке значений. Это не runtime-валидация ответа сервера: `as EditorInput` не проверяет JSON. `nonNullable` также влияет на reset: контрол возвращается к исходному значению, а не null. Для нового редактора этот выбор удобен, однако не нужно применять его к полю, где «ещё не выбрано» действительно моделируется null. [Typed forms](https://angular.dev/guide/forms/typed-forms).

Вложенная группа schedule объединяет start и end, потому что правило порядка относится к их паре. Массив rows хранит одинаково устроенные строки, число которых меняется. Validator отдельного поля не должен искать соседнее поле через глобальную переменную. Validator группы получает текущие значения обоих контролов и возвращает ошибку группы либо null. Validator массива проверяет инвариант между строками. Так изменение ребёнка повторно проверяет соответствующую границу, а UI понимает, где показать объяснение.

## Разобранный пример

Это отдельная учебная группа числового интервала. Числа обозначают условные слоты, не дату или часовой пояс. Пример не содержит готовой реализации всего middle-07:

```ts
import { FormControl, FormGroup, ValidatorFn } from '@angular/forms';

const ordered: ValidatorFn = control => {
  const start = control.get('start')?.value;
  const end = control.get('end')?.value;
  return typeof start === 'number' && typeof end === 'number' && end <= start
    ? { order: true }
    : null;
};

const schedule = new FormGroup({
  start: new FormControl(3, { nonNullable: true }),
  end: new FormControl(5, { nonNullable: true }),
}, { validators: ordered });

console.log(schedule.valid);                   // true
schedule.controls.end.setValue(3);
console.log(schedule.errors);                  // { order: true }
schedule.controls.end.setValue(7);
console.log(schedule.errors);                  // null
// schedule.controls.end.setValue('7');        // ошибка TypeScript
```

Равные границы здесь запрещены: это продуктовый контракт, а не обязательное свойство всех интервалов. Ошибка принадлежит schedule, поэтому `end.hasError('order')` не обязан вернуть true. UI может визуально связать групповую ошибку с обоими полями, не перенося её вручную через setErrors. Ручная подписка, которая меняет errors другого контрола, легко стирает остальные ошибки или создаёт цикл обновлений.

Проверьте мысленно изменение start с 3 на 8 при end=7. Нельзя рассчитывать, что validator выполнится только после изменения end. Затем решите, нужны ли required и конечность чисел для вашей реальной формы. Упражнение фиксирует только указанную политику; полноценная граница DTO обязана проверять остальные входы до создания формы.

## Массив и идентичность

FormArray используется для однородных элементов. Создавайте новую группу для каждой строки: один объект FormGroup, добавленный дважды, не становится двумя независимыми редакторами. Изменения состава делайте через push/removeAt/insert, чтобы дерево контролов и пересчёт оставались согласованными. Стабильный id живёт внутри модели строки и понадобится следующему уроку; индекс нужен для текущего положения, а не для идентичности.

Для duplicateCode определите нормализацию: trim и нижний регистр, пустые строки исключаются из поиска дубликатов. Пустой code при этом всё равно нарушает required. Ошибка duplicateCode относится ко всему rows, а локальная required — к code. При исправлении повтора должна исчезнуть только производная ошибка массива. При удалении строки правило тоже пересчитывается. [FormArray API](https://angular.dev/api/forms/FormArray), [validation](https://angular.dev/guide/forms/form-validation).

Отдельно различайте `value` и `getRawValue()`: disabled-контролы обычно исключены из агрегированного value включённой группы. Включать их обратно в DTO можно только осознанно; отключение id в UI не делает присланный id доверенным серверу. Для full DTO удобен getRawValue с последующим явным mapping, а для PATCH нужно отдельно определить, что именно считается изменением. Dirty не является списком разрешённых серверных полей.

В Java аналогия — отдельная input-модель с Bean Validation и проверкой согласованности полей. Отличие в том, что frontend поддерживает промежуточные invalid-состояния: пользователь ещё вводит значение. Не исправляйте ввод автоматически при каждой ошибке; дайте завершить действие и покажите причину отказа отправки.

## Практика в IDE — middle-07

Откройте `practice/middle/middle-07/README.md`, затем редактируйте только `solution.ts`. Экспортируйте `EditorInput` и `createEditor(input)`. Вход: `{title, schedule:{start,end}, rows:[{id,code,quantity}]}`. Верните настоящую typed FormGroup: title nonnullable с required/minLength(3), schedule с order при end<=start, rows из групп с nonnullable id/code/quantity. Code required; quantity required/min(1); rows получает duplicateCode по описанной нормализации.

Точные типы должны запрещать строку в quantity и число в title. Не скрывайте результат через `any`, `UntypedFormGroup` или широкое приведение типа. Запуск из корня: `npm.cmd run learn -- check middle-07`. Проверка включает реальное поведение Angular и типизацию; одно совпадение JSON формы недостаточно. DOM-шаблон и доступность этим упражнением не проверяются.

## Новые данные и критерии

Проверьте title `Ab`, start/end 9/9, коды ` A-7 ` и `a-7`, quantity 0, затем удаление одной повторной строки и исправление интервала на 9/10. Ожидаются независимые ошибки, которые исчезают после изменения своей причины. Добавьте строку после создания формы и подтвердите пересчёт. Объясните, почему проверка `quantity='2'` должна завершиться ошибкой компиляции, а quantity=0 — ошибкой validation.
