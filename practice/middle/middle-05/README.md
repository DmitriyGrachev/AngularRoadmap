# middle-05 — Реализовать кеш чтения с управляемым временем жизни

## Механизм

Кеш Observable — это ещё и политика подписок. Успешное завершение можно повторить следующему подписчику; ошибка или отмена незавершённого источника не должны оставлять отравленную запись. Invalidation должна отделять поколения запроса.

### Контракт API

`createReadCache(load)` → `{read(key),invalidate(key)}`. key — строка, load(key) возвращает cold Observable одного результата либо ошибку, может бросить синхронно. read возвращает Observable и не вызывает load до подписки. Подписчики одного key делят один активный источник; после успешного complete сохраняется и replay последнего значения. Ошибка передаётся подписчикам, запись удаляется, следующая подписка вызывает новый load. Синхронный throw преобразуется в Observable error. Пока есть хотя бы один подписчик, активный источник не отменяется; после ухода последнего до complete выполняется teardown и запись забывается. invalidate(key) забывает запись для будущих подписок, но не отменяет существующих: они завершаются своим старым значением/ошибкой и не удаляют более новую запись. Ключи независимы. Используйте RxJS, без ручной подписки, живущей вне подписчика.

### Пример и новая проверка

Два подписчика a создают один load; после success третий сразу получает сохранённое значение. Новый пример: invalidate во время a создаёт для нового подписчика новый load, оба поколения могут завершиться в любом порядке.

## Критерии

- Чтение ленивое, параллельные подписки разделяются, success повторяется.
- Ошибки и invalidate позволяют новый запрос без повреждения нового поколения.
- Последний unsubscribe отменяет активный источник; завершённый success остаётся в кеше.

## Подсказки по порядку

1. Внешний defer позволяет выбирать запись Map при каждой подписке.
2. share с ReplaySubject(1) позволяет явно задать reset для error/complete/refCount.
3. При finalize удаляйте только текущую запись и только незавершённый источник.

## После своей попытки

Тесты используют Subject и Observable teardown, без сети и sleeps. В настоящем HttpClient отмена подписки обычно отменяет клиентский запрос, но не гарантирует отмены уже начатой серверной операции.
