# Отдельный рабочий пример

Откройте два терминала в корне:

```powershell
npm.cmd run practice:api
npm.cmd run practice:demo
```

Пример: `http://127.0.0.1:4303`. Учебная заготовка остаётся в `practice/issue-tracker`; готовый пример не импортируется ни оттуда, ни в сайт курса.

Работают список, поиск с debounce и отменой устаревшего HTTP-запроса через `switchMap`, фильтры/страницы в URL, состояния loading/empty/error/success, повтор запроса, прямые ссылки на детали и 404. Создание/редактирование используют typed Reactive Forms; повторная отправка блокируется во время pending, ошибки поля связаны с input через `aria-describedby`, введённый текст сохраняется при 400/500.

В списке откройте «Учебные сценарии API» для медленного ответа, 500 и пустого результата. В форме «Учебный сценарий отправки» включает задержку, 400 с fieldErrors и 500. После ошибки выберите обычный сценарий и повторите отправку без повторного ввода.

Изменения сохраняются в памяти Java-процесса; перезапуск API восстанавливает 32 исходные заявки. PATCH по контракту меняет title/status/priority, поэтому поле description доступно при создании. Это пример изучаемых механизмов, без авторизации и базы данных.

Unit-тесты эталона: `npx.cmd ng test issue-demo --watch=false`. Проверяются параметры GET, обработка 500, POST и сохранение черновика/блокировка повторной отправки при 400. Полная браузерная проверка с тремя запущенными процессами (API, demo, student): `node author/solutions/issue-tracker/verify.mjs`; при необходимости переменная `PLAYWRIGHT_CHROMIUM_EXECUTABLE` задаёт путь к установленному Chromium. Для стандартной версии установите браузер командой `npx.cmd playwright install chromium`.
