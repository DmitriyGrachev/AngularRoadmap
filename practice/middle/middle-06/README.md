# middle-06 — Сериализовать записи и восстановиться после отказа

## Механизм

Параллельные записи нарушают порядок, switchMap теряет ожидание результата прежней записи. Очередь concatMap ждёт завершения каждого запроса. Ошибка должна стать результатом конкретной команды, чтобы очередь продолжила работу.

### Контракт API

`serializeWrites(commands$,save)` возвращает Observable результатов. Команды имеют уникальный id и любые поля, save получает исходный объект. Успешный save — Observable с одним значением и complete; ошибка может быть Observable error или синхронный throw. До подписки ничего не запускается. Записи запускаются строго по одной в порядке команд. Успех даёт `{id,ok:true,value}`, отказ `{id,ok:false,error:"save-failed"}`, без текста исходной ошибки. После отказа запускается следующая запись. Завершение commands$ дожидается очереди. Unsubscribe отменяет активную внутреннюю подписку, отписывается от commands$ и не запускает оставшиеся команды. Используйте RxJS. Этот контракт не моделирует idempotency или rollback на сервере.

### Пример и новая проверка

Команды a,b,c пришли сразу; пока a не complete, b не запускается. Ошибка b становится одним failed result, c всё равно выполняется. Новый пример: save(a) бросает до возврата Observable — b должен пройти.

## Критерии

- Активна только одна запись; итоговые события сохраняют порядок команд.
- Внутренняя ошибка и синхронный throw не завершают всю очередь.
- Отписка прекращает активную работу и отбрасывает очередь.

## Подсказки по порядку

1. За порядок отвечает concatMap, а не mergeMap.
2. defer откладывает save и перехватывает синхронный throw.
3. catchError размещается внутри concatMap и возвращает of результата отказа.
