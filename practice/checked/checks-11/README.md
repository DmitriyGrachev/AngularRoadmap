# Сделать поиск с debounce и отменой старого чтения

Урок w4-04, около 45 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

Ввод опережает сеть. debounceTime ждёт паузу, distinctUntilChanged исключает одинаковые нормализованные строки, switchMap отписывается от прежнего чтения. Отписка прекращает доставку событий; транспорт решает, прерывать ли HTTP. Promise и Java CompletableFuture не дают поведения switchMap автоматически. Виртуальные часы RxJS делают проверку гонок воспроизводимой.

### Контракт API

searchIssues(queries$,search) возвращает Observable. Нормализуйте trim, затем debounceTime(30), затем distinctUntilChanged. Непустой query вызывает search(query):Observable<Issue[]> через switchMap; сначала {kind:"loading",query}, затем {kind:"ready",query,items}. Пустой query выдаёт только {kind:"ready",query:"",items:[]} без вызова search. Новое значение отменяет старое чтение после debounce. Ошибки search здесь могут завершать поток: восстановление изучается в checks-12.

### Пример и новая проверка

" api " и последующее "api" вызывают сеть один раз. Новый пример: очистите строку, пока медленный запрос ждёт ответа — старый результат не должен появиться.

Из корня проекта выполните `npm.cmd run learn -- check checks-11`. Редактируйте только `practice/checked/checks-11/solution.mjs`. Сначала запишите прогноз или собственную попытку в тренажёре. Отчёт сохраняется в practice/reports и не отмечает урок освоенным автоматически.

## Условия приёмки

- Trim предшествует сравнению, debounce равен 30ms.
- Результат отменённого чтения не попадает в выдачу.
- Пустой запрос не вызывает сеть и выдаёт ready с [].
