# HttpClient и Observable: когда начинается запрос

120 минут. Результат: сервис загружает список и детали, а вы можете объяснить количество запросов. Нужны [HTTP](/lessons/w4-01), [DI](/lessons/w3-04), [Promise](/lessons/w2-02).

## Ситуация и прогноз

Вызвали `const request$ = http.get('/api/issues')`, но в Network ничего нет. Затем дважды подписались на `request$` и увидели два GET. Предскажите причину: возвращённый объект описывает работу, каждая подписка запускает её заново. Само присваивание переменной не отправляет запрос.

## Observable без мистики

Observable — источник, на который подписываются для получения значений. Подписчик может получить `next`, затем `complete`, либо `error`. После завершения или ошибки обычный поток больше не отправляет значений. HTTP обычно выдаёт один результат тела и завершается. Другие Observable, например изменения маршрута или ввода, могут выдавать много значений и жить столько же, сколько компонент.

Promise представляет один будущий исход; работа часто начинается при создании Promise. Observable может описывать отложенную работу, последовательность и отмену через unsubscribe. Это не значит, что любой Observable ленивый или что все источники одинаковы: Subject и события имеют другие особенности. В этом уроке важен конкретный контракт HttpClient: холодный запрос начинается при подписке, а каждая подписка независима.

`HttpClient` предоставляется через DI. В standalone-приложении вызов `provideHttpClient()` включают в providers bootstrap/конфигурации приложения. Импорт класса в файле сервиса не регистрирует provider. Ошибка «No provider» говорит об окружении DI, а не о недоступном Java API. Сервис получает клиент через `inject(HttpClient)` и возвращает Observable, оставляя решение о подписке потребителю.

`get<Page<Issue>>()` сообщает компилятору ожидаемый тип. Angular не сверяет весь JSON с этим интерфейсом. На границе внешних данных тип и контракт нужно согласовать, а для ненадёжного API добавить проверку действительно используемых полей. Не лечите несовпадение `items` и `content` приведением `as any`: это отключит подсказку именно там, где она полезна.

## Разобранная демонстрация

Полная выполняемая модель холодного источника находится в `practice/angular-labs/scripts/w4-02.ts`. Запуск из корня: `node practice/angular-labs/scripts/w4-02.ts`. Ожидаются два сообщения «Запуск источника» и результаты `A 1`, `B 1`. Java API не требуется.

Сервис `BookApi` ниже — отдельный законченный класс из `practice/angular-labs/src/demos/book-api.ts`, но он не является самостоятельно запускаемым приложением. Настоящего `/api/books` учебный API не содержит. Его транспорт воспроизводится в соседнем `book-api.spec.ts`: `npm.cmd run practice:labs:test` запускает четыре проверки лаборатории, включая две независимые подписки BookApi. Так пример HTTP можно выполнить без вымышленного endpoint. В Node-файле сохранена только последняя, не содержащая декораторов часть следующего блока.

```ts
import { Injectable, inject } from '@angular/core';
import { HttpClient, HttpParams } from '@angular/common/http';
import { Observable, defer, of } from 'rxjs';

type Book = { id: string; title: string };
type BookPage = { items: Book[]; total: number };

@Injectable({ providedIn: 'root' })
export class BookApi {
  private http = inject(HttpClient);
  list(q: string): Observable<BookPage> {
    const params = new HttpParams().set('q', q);
    return this.http.get<BookPage>('/api/books', { params });
  }
}

const demo$ = defer(() => {
  console.log('Запуск источника');
  return of<BookPage>({ items: [{ id: 'b1', title: 'Сети' }], total: 1 });
});
demo$.subscribe(page => console.log('A', page.total));
demo$.subscribe(page => console.log('B', page.total));
```

Последние строки выполняются указанной командой Node. Они выводят «Запуск источника», `A 1`, затем снова «Запуск источника», `B 1`. `defer` создаёт работу при каждой подписке; `of` синхронно выдаёт подготовленное значение и завершается. Это маленькая модель, а не утверждение, что настоящий HTTP синхронный.

В `HttpParams` методы возвращают новый объект. Запись `params.set('q', q)` без присваивания не меняет прежний экземпляр. Цепочка в примере сохраняет результат. Вариация: добавьте `.set('page', 0)` и убедитесь, что результирующая строка содержит оба параметра. Не кодируйте q вручную перед передачей клиенту: двойное кодирование изменит запрос.

## Где подписываться

Одна пользовательская загрузка должна иметь одного понятного владельца подписки. Если сервис подписался внутри и компонент снова подписался на возвращённый Observable, возможны два независимых запроса и два пути ошибок. Пусть сервис возвращает описание HTTP-операции, а компонент задаёт состояние ожидания и результат либо использует `async` pipe. `async` сам управляет подпиской; не добавляйте рядом вторую подписку «на всякий случай».

Отписка от незавершённого HTTP обычно отменяет браузерный запрос. Это освобождает ресурсы и предотвращает обработку результата уничтоженной страницы. Она не гарантирует, что сервер ничего не сделал, особенно при записи. GET чтения и POST изменения имеют разные последствия, к ним вернёмся при формах.

Ошибка запроса приходит в error callback, а не как пустой успешный массив. Для детали 404 можно показать отсутствие, для 500 — сбой, для недоступного ответа — сетевое объяснение. Если всё превращать в `[]`, пользователь увидит «ничего нет» даже при падении сервера.

## Мост от Java

Observable напоминает композицию отложенных операций, но не является Java Stream. Stream часто обрабатывает уже имеющийся набор и потребляется терминальной операцией; Observable может представлять будущие события и отменяемую асинхронную работу. Сходство `map` не делает их временем выполнения одинаковыми. Не пытайтесь получить результат HTTP синхронным `return` из subscribe.

## Критерии ручной проверки

Список и детали берутся из API; тип соответствует envelope; нет скрытых подписок в сервисе; количество GET объяснено; 404 не выдаётся за пустой список; provider зарегистрирован штатно.
