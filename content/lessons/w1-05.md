# Форма фильтра и поиск ошибки в браузере

**Результат:** вы делаете доступный фильтр статуса и находите ошибку через Console и breakpoint, то есть точку останова. Нужны [события](/lessons/w1-03) и [операции массивов](/lessons/w1-04). Здесь соединяются форма, данные и отображение, без сервера и Angular.

## Рабочая ситуация и прогноз

Пользователь выбирает «Открытые», нажимает Enter и получает только нужные заявки. У коллеги вместо фильтра страница перезагружается, а у другого код падает ещё до первого нажатия.

```html
<form id="filters">
  <button>Применить</button>
</form>
```

Какой тип у кнопки внутри формы по умолчанию? Чем отличается обработчик клика кнопки от обработчика отправки формы? Как ведёт себя страница при отправке без JavaScript? Предположите ответы, затем проверьте их на примере.

## Форма описывает ввод

`form` объединяет связанные поля и отправку. `label` даёт полю понятное имя. Атрибут `for` у подписи должен точно совпадать с `id` поля. Пользователь сможет нажать подпись, чтобы перевести фокус к полю; средство чтения с экрана получит его имя. Placeholder внутри input этого не заменяет: он исчезает при вводе и имеет другую роль. `name` — имя поля в данных отправки, `id` — идентификатор элемента в документе; это независимые атрибуты.

`input` подходит для ввода строки, `select` — для выбора из вариантов. Каждый `option` имеет видимый текст и машинное `value`: пользователь видит «Открытые», а код получает `OPEN`. Разделение позволяет оставить контракт статусов стабильным при переводе интерфейса. В нашем фильтре `ALL` обозначает отсутствие ограничения, это не статус самой заявки. Значение свойства `select.value` всегда строка, поэтому сравнение со строковым статусом ожидаемо.

Кнопка с `type="submit"` отправляет форму. Кнопка с `type="button"` этого не делает. Без явного типа обычная кнопка внутри формы часто ведёт себя как submit; задавайте тип явно, чтобы назначение было видно при чтении. Действие отправки может возникнуть клавиатурой, поэтому основной сценарий фильтра вешаем на событие `submit` формы. Так мышь и клавиатура проходят одну функцию.

## Событие и действие по умолчанию

Браузер передаёт обработчику объект события. Он содержит сведения о случившемся и методы управления поведением. В обработчике submit вызов `event.preventDefault()` отменяет стандартную отправку с навигацией. Он не отменяет выполнение нашего JavaScript и не «исправляет все события». После него читаем значение поля, выбираем данные и обновляем результат.

Не храните отдельный изменяемый «отфильтрованный исходник», из которого потом снова фильтруете: возврат к ALL тогда потеряет ранее скрытые элементы. Сохраняйте полный массив как источник, а видимый список вычисляйте по текущему значению поля. Результат отсутствия совпадений тоже является состоянием интерфейса. Пустая область без текста выглядит как поломка; сообщение «Заявок нет» объясняет результат.

Атрибут `aria-live="polite"` у результата позволяет вспомогательным технологиям сообщить об обновлении без принудительного перемещения фокуса. Он не создаёт видимую подпись и не заменяет обычный понятный текст. Проверяйте базовый путь клавиатурой: Tab переводит фокус, стрелки меняют выбор, Enter отправляет форму. Не убирайте outline без полноценной замены: иначе пользователь потеряет текущую позицию.

## Ошибка — наблюдаемый факт

Console показывает сообщение и место ошибки. Ошибка чтения свойства у null обычно значит, что поиск DOM-элемента не дал результата. Проверяйте точный селектор, существование id и момент выполнения. Если регистрация обработчика упала, дальнейшее нажатие не может запустить незарегистрированную функцию. Сначала устраняется первая ошибка загрузки, затем исследуется поведение.

Во вкладке Sources можно поставить breakpoint на строку обработчика. Когда выполнение остановится, браузер покажет текущие переменные и стек вызовов. Шаг вперёд позволяет проверить значение до и после filter. Это отличается от догадки по итоговой картинке: теперь известен конкретный вход и выбранная ветка. Снимите breakpoint после исследования, чтобы не принять намеренную паузу за зависание страницы.

## Мост от Java

Форма похожа на объект ввода по набору полей, но DOM-поля содержат строки и не являются Java DTO. HTML-валидация помогает пользователю, однако не защищает сервер: запрос можно отправить в обход страницы. Обработчик события знаком по listener, а breakpoint работает по той же идее, что отладчик JVM. При этом DevTools исследует код вкладки, отдельно от отладчика Java backend.

## Разобранный пример

Откройте [фильтр](http://127.0.0.1:4301/foundations/web-basics/examples/forms.html), исходник `practice/foundations/web-basics/examples/forms.html`. После загрузки видно «Письмо, Кнопка». При выборе OPEN и отправке остаётся «Письмо», DONE — «Кнопка», ALL возвращает обе. Функция `render` каждый раз читает исходный массив. `join(', ')` соединяет строки разделителем, чтобы вывести простой текст вместо HTML-разметки.

Поставьте breakpoint внутри render, выберите DONE, нажмите Enter. На паузе проверьте `selected` и `visible.length`: ожидаются `DONE` и 1. Для вариации добавьте в пример временную опцию IN_PROGRESS — получите «Заявок нет». Это нормальный результат фильтра, а не исключение. Верните демонстрационный файл после опыта.

Сначала найдите намеренный дефект селектора по сообщению Console и исправьте его. Затем добавьте связанный label и select с ALL, OPEN, DONE. Реализуйте submit без перезагрузки, видимый результат и пустое состояние. Для проверки пустого состояния временно используйте статус, которого нет в массиве.

## Критерии

- Исходная ошибка объяснена через конкретный null и несовпадение id, Console после исправления чиста.
- ALL возвращает полный список после нескольких переключений; выбранный статус фильтрует корректно.
- Есть подпись поля, всё действие выполняется клавиатурой без перезагрузки.
- Вы остановились в обработчике и назвали фактическое значение выбранного статуса; проверка ручная.

## Проверка понимания

1. Чем id отличается от name?
2. Почему submit предпочтительнее одного click для основного действия формы?
3. Что отменяет preventDefault и чего он не отменяет?
4. Почему повторный фильтр нужно вычислять от полного массива?

Новая вариация: добавьте текстовый input для поиска в названии. Сначала сформулируйте, как сочетаются статус и поиск, затем проверьте пустую строку и отсутствие совпадений.
