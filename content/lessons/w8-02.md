# URL как состояние: нормализация, история и roundtrip

180 минут: 35 на контракт, 30 на пример, 85 на реализацию и 30 на новые данные. Предыдущий шаг — [Signals store](/lessons/w8-01). Результат: фильтры переживают копирование ссылки, обновление и Back/Forward, а чтение и запись URL согласованы.

## Одна функция, несколько точек входа

Пользователь может изменить фильтр кнопкой, открыть чужую ссылку или нажать Back. Если код обновляет список только в обработчике кнопки, два остальных сценария остаются без поддержки. URL — внешний ввод, который нужно разобрать и нормализовать. Затем из одной нормализованной модели строятся поля фильтров и запрос данных. Обработчик UI выражает намерение изменить URL; подписка на маршрут делает остальные действия.

Не всё состояние следует помещать в адрес. Поиск, сортировка и номер страницы полезны для воспроизведения списка. Открытое меню, текущий фокус и промежуточный неотправленный текст могут оставаться локальными. Секреты и приватные данные не добавляют в query string: адрес попадает в историю, логи и скопированные ссылки. Решение о состоянии URL принимается по пользовательскому сценарию, а не по желанию сериализовать весь store.

Отсутствующий параметр отличается от строки `'null'`, пустой строки и повторённого параметра. `URLSearchParams.get` читает одно значение, getAll — все. Для множественного статуса естественна запись `status=OPEN&status=DONE`. Преобразование через Object.fromEntries теряет повторы. В задаче нужно сохранить неизвестные параметры тоже с повторами: другая часть приложения может использовать два значения tag. Удалить их ради удобства собственного parser означает сломать соседнюю функцию.

## Нормализация определяет канонический вид

Пусть внутреннее состояние всегда содержит trimmed q, уникальные разрешённые statuses в фиксированном порядке, неотрицательную страницу, один из размеров 10/25/50 и известную сортировку. Некорректный внешний ввод получает записанные значения по умолчанию. После этого API и компонент не должны каждый раз по-своему исправлять page. Такой единый контракт уменьшает число возможных состояний.

Проверки `Number(value)` недостаточно для строгого десятичного page: строка `1e2`, пробел или `0x10` может превратиться в число, хотя такой URL не согласован. Сначала определите допустимую запись, затем диапазон safe integer. Не применяйте parseInt без проверки всей строки: `12cats` не становится корректной страницей от того, что начальные цифры распознаны. При записи runtime-значения также нормализуют: интерфейс TypeScript не защищает от ошибочного JS-вызова.

Закон roundtrip имеет вид `read(write(url, filters)) = normalize(filters)`. Второй закон полезен для идемпотентности: повторная запись нормализованного состояния не меняет адрес снова. Это не означает побайтовое сохранение исходной строки: URLSearchParams может изменить способ percent-encoding. Сохраняться должны путь, fragment и семантика сторонних параметров. Значения по умолчанию обычно опускают, чтобы адрес оставался коротким и единственным для одного состояния.

В Java это напоминает преобразование query params в типизированный request DTO. Отличие — браузерная история является частью продукта. `replaceUrl` заменяет текущую запись, обычная навигация добавляет новую. Для каждого символа живого поиска новая запись часто неудобна, для подтверждённого фильтра Back может быть ожидаем. Запишите политику и проверьте её: случайный выбор флага меняет поведение пользователя, даже если текущая таблица выглядит правильно.

## Разобранный пример

Следующий пример работает в Node. Сохраните `url-demo.mjs` в собственной временной папке и выполните `node url-demo.mjs`:

```js
const url = new URL('/issues?tag=a&tag=b&q=%20VPN%20#results', 'https://lesson.test');
const q = (url.searchParams.get('q') ?? '').trim();
url.searchParams.delete('q');
if (q) url.searchParams.set('q', q);
url.searchParams.delete('status');
for (const status of ['OPEN', 'DONE']) url.searchParams.append('status', status);
console.log(url.pathname);
console.log(url.searchParams.getAll('tag').join(','));
console.log(url.searchParams.get('q'));
console.log(url.searchParams.getAll('status').join(','));
console.log(url.hash);
```

Ожидаются `/issues`, `a,b`, `VPN`, `OPEN,DONE` и `#results`. Пример демонстрирует сохранение повторов и fragment, но не реализует полный parser. В упражнении дополнительно нужны дефолты, строгие числа и нормализация неизвестных статусов. Поменяйте tag на собственное имя: функция, владеющая фильтрами, не должна случайно присвоить себе чужой параметр.

В Angular читайте изменяемые query params из route-потока. Snapshot — снимок момента чтения; если компонент переиспользуется, он не обновится автоматически как сохранённая переменная. При синхронизации формы из маршрута отключайте emitEvent, когда это предотвращает обратную навигацию. Иначе маршрут обновит форму, форма снова обновит маршрут и создаст лишнюю работу. Это не повод подавить все события формы навсегда: различайте пользовательское намерение и применение внешнего состояния.

## Практика в IDE — middle-04

Реализуйте `readRoute(url)` и `writeRoute(url, filters)` в `practice/middle/middle-04/solution.mjs`. Рядом в README зафиксированы формы входа и выхода. Модель содержит q, statuses, page, pageSize и sort. Разрешённые statuses — OPEN, IN_PROGRESS, DONE в этом каноническом порядке; page начинается с нуля, pageSize по умолчанию 25, sort по умолчанию updated. При записи опускайте значения по умолчанию, сохраняйте чужие повторяющиеся параметры, путь и hash.

Проверка: `npm.cmd run learn -- check middle-04`. Сначала напишите на бумаге адрес с двумя статусами, tag-повторами, дальней страницей и fragment. Предскажите результат чтения, затем результат записи дефолтов поверх этого адреса. Не переносите автоматически соглашение workplace: там page начинается с единицы. Один продукт может иметь другую модель, но адаптер обязан явно выполнять преобразование.

## Критерии самопроверки

Обязательны строгий разбор, канонические повторы, сохранение чужих параметров и оба roundtrip-свойства. Самостоятельный уровень подтверждается объяснением истории и отсутствия цикла форма ↔ маршрут. При работе с подсказками повторите задачу на другом наборе разрешённых сортировок. Если приложение работает только после нажатия собственной кнопки, задача ещё не завершена: адрес является самостоятельным входом в функцию.
