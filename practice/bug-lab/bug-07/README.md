# bug-07: В адресе B-2, в деталях всё ещё A-1

Связанный урок: [w3-05](../../../content/lessons/w3-05.md). Около 35 минут; упражнение может заменить часть ручной практики урока.

Симптом: /issues/A-1 открывается правильно; переход к /issues/B-2 меняет адрес, но не данные. Запустите node practice/bug-lab/bug-07/repro.mjs: paramMap меняется у того же route. До правки request вызван только для A-1. Исправьте details: новый ID запускает чтение, повтор того же ID не дублирует его, старый поздний ответ не попадает в результат.

## Запуск из корня проекта

```powershell
node practice/bug-lab/bug-07/repro.mjs
npm.cmd run learn -- check bug-07
```

Сценарий работает без сайта, dev server и Java API с установленными зависимостями проекта. Исходный дефект намеренно завершает repro с AssertionError и ненулевым кодом. После исправления сценарий завершается успешно. Полная проверка создаёт отчёт версии 1 для учебного сайта.

Редактируйте только `solution.mjs`. `starter.mjs` сохраняет исходную поломку для проверки качества задания и не зависит от вашего решения. Существующее приложение ученика не используется и не переписывается.

## Контракт

details(route, request) возвращает Observable<Issue>. route содержит snapshot.paramMap и paramMap, request(id) — Observable детали. Входной маршрут здесь всегда содержит непустой допустимый id.

## Критерии результата

- A-1 → B-2 загружает обе детали без пересоздания модели.
- Повтор того же ID не запускает лишнее чтение.
- Смена ID отписывает незавершённый старый запрос и игнорирует его поздний ответ.

## Диагностика

Перед изменением запишите ожидаемое и фактическое поведение, гипотезу причины и эксперимент, различающий две возможные причины. После исправления запустите полную проверку, а не только один repro. Три последовательные подсказки и объяснение находятся в тренажёре; сначала сохраните собственную попытку.

## Новый регрессионный пример

Регрессионная задача: отправьте A-1, затем B-2 и завершите B-2 раньше A-1. В результате должна быть только B-2. Дополнительно откройте обе ссылки в приложении и найдите место обработки отсутствующего ID.
