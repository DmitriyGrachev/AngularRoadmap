# Собрать store на настоящих signals/computed

Урок w3-03, около 35 минут. Может заменить часть ручной практики урока.

## Механизм и мост из Java

signal хранит исходное значение; computed кеширует результат и зависимости, прочитанные во время вычисления. Не храните visible/openCount в отдельных writable-сигналах: ручная синхронизация создаёт рассогласование. В отличие от обычного Java getter, чтение signal внутри computed регистрирует зависимость. Мутация массива по прежней ссылке может оставить computed устаревшим.

### Контракт API

createIssueStore(initial) возвращает {issues,query,visible,openCount,replaceStatus}. issues/query — реальные writable signals из @angular/core; query начинается с "". visible — computed-фильтр по title без учёта регистра и с trim запроса; пустой запрос показывает всё. openCount — computed количества OPEN во всём issues независимо от query. replaceStatus(id,status) обновляет одну запись без мутации initial. Повторное чтение visible без изменения зависимостей возвращает тот же массив.

### Пример и новая проверка

" фОРМа " показывает «Форма», но openCount считает весь список. Новый пример: выполните issues.set с новым массивом и прочитайте оба computed.

## Условия приёмки

- Возвращаются реальные Angular signals.
- Производные данные обновляются после set и replaceStatus.
- Вход не мутирует, computed кеширует повторное чтение.
