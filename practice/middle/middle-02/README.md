# middle-02 — Проверить DTO и преобразовать дату на границе

## Механизм

HTTP boundary принимает unknown. После проверки данные можно привести к удобной модели UI; interface или assertion не выполняет валидацию. Уникальность ID нужна для tracking, selection и сопоставления ошибок, даже если сервер обычно гарантирует её.

### Контракт API

Экспортируйте `decodeIssues(input)` → `{ok:true,value:Array<{id:string,title:string,createdAt:Date}>}` либо `{ok:false,error:"invalid-data"}`. Вход — массив обычных JSON-подобных объектов с непустыми после trim строками id/title и строкой createdAt строго YYYY-MM-DD. Дата должна существовать в календаре; дата превращается в новый Date в UTC, 00:00:00.000. id/title нормализуются trim; ID уникальны после нормализации. Лишние поля игнорируются в результате. При любой плохой записи отклоняется весь массив, без исключения и частичного успеха. Пустой массив допустим. Вход не мутирует, каждый вызов создаёт собственные Date.

### Пример и новая проверка

"2024-02-29" допустима, "2023-02-29" и "2024-02-30" нет. ID "a" и " a " конфликтуют. Новый пример: измените год Date из первого результата — второй результат и исходная строка остаются прежними.

### Работа

Из корня проекта выполните `npm.cmd run learn -- check middle-02`. Редактируйте только `practice/middle/middle-02/solution.mjs`; starter остаётся исходной точкой. Сначала запишите прогноз или собственную попытку. JSON-отчёт появится в practice/reports; импорт отчёта не означает самостоятельное освоение урока.

## Критерии

- Форма и все записи проверены до допуска в модель.
- Дата проверяется по календарю, ID — после trim.
- Выход содержит только id/title/createdAt и не разделяет изменяемые даты между вызовами.

## Подсказки по порядку

1. Отдельно исключите null, массив вместо записи и неправильный тип поля.
2. Date может нормализовать 30 февраля: сравните сериализованный YYYY-MM-DD с исходным.
3. Set хранит уже нормализованные ID; итог формируйте в новом массиве.

## После своей попытки

Успех означает согласованный UI DTO, а не только корректный JSON. Вызов не доказывает контракт реального backend; добавьте API contract test в интеграционном задании.
