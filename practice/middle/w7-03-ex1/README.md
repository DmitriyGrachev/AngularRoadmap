# Доступный адаптивный список

Ручное задание к уроку [w7-03](../../../content/lessons/w7-03.md). Исправить один воспроизводимый дефект переполнения и один дефект управления клавиатурой. Панель фильтров и список остаются пригодными при 320, 768 и 1280 CSS-пикселях.

## Где работать

Реализация находится в вашей версии `practice/workplace`: src/app/list-page.ts, src/app/list-page.html и стили, которые действительно задают геометрию списка. Эта папка задания хранит только условия и `notes.md` с доказательствами. Наличие заполненных заметок само по себе не подтверждает работу функции. Не заменяйте свои исходники авторским решением; сохраните предыдущие выполненные изменения.

```text
npm.cmd run practice:workplace
npm.cmd run test:workplace
npm.cmd run build:workplace
```

Адрес: http://127.0.0.1:4305. DeskApi — асинхронный сервис в памяти: запросов GET/PATCH в Network нет, reload восстанавливает seed. Для порядка и числа операций используйте управляемый fake API или spy. Это не проверка HTTP, БД или двух серверных клиентов. Страница начинается с 1, статусы — open/in-progress/closed; не переносите контракт middle-04 без адаптации.

## Требования

1. Сначала запишите причину переполнения по DOM/Computed, а не предположение по внешнему виду.
2. У полей есть связанные подписи; действие использует кнопку, переход — ссылку; Tab-порядок понятен и фокус видим.
3. Длинный текст доступен для чтения. Если нужен горизонтальный скролл, он ограничен нужным контейнером и доступен клавиатурой.
4. Загрузка, ошибка и повтор не оставляют пользователя без понятной точки взаимодействия.

## Проверка на новых данных

- 180 букв без пробелов при ширине 320.
- 30 слов с пробелами при масштабе 200%.
- Пустой результат и один отказ чтения.
- Полный путь по фильтрам и строкам только клавиатурой.

До кода запишите ожидаемое поведение, затем реализуйте и сравните результат. Если временные свойства проверяются тестом, управляйте завершением операций вручную; случайные задержки не доказывают отсутствие гонки. Baseline-тесты не являются оценкой новой функции.

## Что сохранить в notes.md

До/после для двух дефектов, DOM-причина, результаты новых данных, поведенческий тест при изменении обработчиков и честная отметка о проверке скринридером. Укажите команды и фактический результат, а также ограничения. Не копируйте служебные исходники и реальные данные работодателя.

## Рубрика

По каждому требованию отметьте «самостоятельно», «с подсказкой» либо «нужна повторная попытка» и приведите наблюдаемое доказательство. Обязательные свойства нельзя компенсировать красивым интерфейсом или количеством тестов. Полные критерии и три последовательные подсказки находятся в уроке. Для этой задачи автоматического выставления оценки через `learn check` нет; после собственной попытки выполните ручную проверку и отметку в платформе.
