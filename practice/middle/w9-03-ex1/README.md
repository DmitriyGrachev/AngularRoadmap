# Повтор чтения и защита от устаревшего ответа

Ручное задание к уроку [w9-03](../../../content/lessons/w9-03.md). Добавить повтор ошибочного чтения текущих фильтров без изменения URL и доказать правильное состояние при отмене.

## Где работать

Реализация находится в вашей версии `practice/workplace`: src/app/list-page.ts, list-page.html и проверки страницы. Эта папка задания хранит только условия и `notes.md` с доказательствами. Наличие заполненных заметок само по себе не подтверждает работу функции. Не заменяйте свои исходники авторским решением; сохраните предыдущие выполненные изменения.

```text
npm.cmd run practice:workplace
npm.cmd run test:workplace
npm.cmd run build:workplace
```

Адрес: http://127.0.0.1:4305. DeskApi — асинхронный сервис в памяти: запросов GET/PATCH в Network нет, reload восстанавливает seed. Для порядка и числа операций используйте управляемый fake API или spy. Это не проверка HTTP, БД или двух серверных клиентов. Страница начинается с 1, статусы — open/in-progress/closed; не переносите контракт middle-04 без адаптации.

## Требования

1. Повтор читает текущий запрос без случайного параметра времени и без новой записи истории.
2. Во время активного повтора кнопка недоступна; изменение фильтра остаётся возможным и заменяет чтение.
3. Ошибка одного чтения не завершает обработку будущих фильтров и повторов.
4. Старый ответ не отображается; cleanup A не скрывает загрузку B.
5. Уничтожение компонента освобождает принадлежащую ему подписку; фокус после повтора остаётся понятным.

## Проверка на новых данных

- 503 через панель среды, затем успешный повтор с тем же URL.
- Быстрые VPN→DNS, старый ответ завершён последним.
- A отменён, B ещё loading.
- Уничтожение во время чтения с проверенным teardown.

До кода запишите ожидаемое поведение, затем реализуйте и сравните результат. Если временные свойства проверяются тестом, управляйте завершением операций вручную; случайные задержки не доказывают отсутствие гонки. Baseline-тесты не являются оценкой новой функции.

## Что сохранить в notes.md

Управляемый fake API/spy с количеством вызовов, тест старого ответа и loading, URL до/после повтора, клавиатурный сценарий. Укажите команды и фактический результат, а также ограничения. Не копируйте служебные исходники и реальные данные работодателя.

## Рубрика

По каждому требованию отметьте «самостоятельно», «с подсказкой» либо «нужна повторная попытка» и приведите наблюдаемое доказательство. Обязательные свойства нельзя компенсировать красивым интерфейсом или количеством тестов. Полные критерии и три последовательные подсказки находятся в уроке. Для этой задачи автоматического выставления оценки через `learn check` нет; после собственной попытки выполните ручную проверку и отметку в платформе.
