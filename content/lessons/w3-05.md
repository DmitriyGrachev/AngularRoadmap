# Router: URL как часть состояния

120 минут. Результат: список и детали доступны напрямую, фильтр переживает обновление страницы. Нужны [DI и сервис](/lessons/w3-04).

## Ситуация и прогноз

Вы открыли детали из списка, скопировали адрес коллеге, но после перезагрузки видите пустой экран. Возможно, выбранная запись жила только в поле компонента. Предскажите, что нужно сохранить в URL, чтобы приложение могло восстановить страницу без истории ваших нажатий. Для детали нужен ID; для списка — существенные фильтры и позже номер страницы.

## Маршрут и навигация

Router сопоставляет путь с конфигурацией routes и создаёт соответствующий компонент в `router-outlet`. Путь `books/:id` содержит переменный сегмент; `/books/b9` передаёт строку `b9`. Query parameters идут после `?`, например `?category=network`. Они не участвуют в выборе компонента тем же способом, что сегменты пути, но описывают его состояние.

Порядок routes важен: применяется первое подходящее правило. Статический `books/new` нужно расположить до `books/:id`, иначе слово `new` будет принято за ID. Пустой путь с перенаправлением обычно требует `pathMatch: 'full'`, чтобы не перенаправлять любой путь по совпавшему пустому префиксу. Неизвестный маршрут закрывают `**` в конце, иначе он поглотит более точные правила.

`RouterLink` строит переход внутри приложения, позволяя Router управлять историей без полной загрузки документа. Обычная ссылка остаётся правильным элементом для навигации: она работает с клавиатурой и поддерживает открытие в новой вкладке. Не заменяйте её `div` с click. Кнопка подходит для действия, ссылка — для перехода. `RouterOutlet` и `RouterLink` нужно включить в imports использующего их компонента.

ActivatedRoute предоставляет параметры текущего маршрута. `snapshot` — фотография в определённый момент. Если Router использует тот же экземпляр компонента при переходе между разными ID, чтение snapshot только в constructor не обновит данные. Поток `paramMap` сообщает последующие изменения. Для локальной демонстрации подпишемся на него; на следующей неделе свяжем изменение ID с HTTP через `switchMap`.

## Разобранная демонстрация

Полные файлы уже сохранены: `practice/angular-labs/src/demos/library-routes.ts` и соседний `book-page.ts`. Запустите `npm.cmd run practice:labs`, откройте `http://127.0.0.1:4304/books`. Ссылка ведёт к `/books/b9`; прямой `http://127.0.0.1:4304/books/b10` показывает «Книга b10» и переживает обновление вкладки. Это отдельная библиотечная демонстрация; routes трекера менять не нужно.

```ts
import { Component } from '@angular/core';
import { RouterLink, Routes } from '@angular/router';
import { BookPage } from './book-page';

@Component({
  selector: 'library-page', standalone: true, imports: [RouterLink],
  template: `<a [routerLink]="['/books', 'b9']">Книга b9</a>`,
})
export class LibraryPage {}

export const libraryRoutes: Routes = [
  { path: 'books', component: LibraryPage },
  { path: 'books/:id', component: BookPage },
  { path: '', redirectTo: 'books', pathMatch: 'full' },
  { path: '**', redirectTo: 'books' },
];
```

В готовой лаборатории `src/main.ts` вызывает `provideRouter`, а `src/app.ts` включает libraryRoutes в общую конфигурацию и показывает `router-outlet`. Второй bootstrap не нужен. Вот полное содержание страницы детали из `book-page.ts`:

```ts
import { Component, inject, signal } from '@angular/core';
import { ActivatedRoute, RouterLink } from '@angular/router';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

@Component({
  selector: 'book-page', standalone: true, imports: [RouterLink],
  template: `
    <a routerLink="/books">К списку</a>
    <h2>Книга {{ id() }}</h2>
  `,
})
export class BookPage {
  id = signal('');
  private route = inject(ActivatedRoute);
  constructor() {
    this.route.paramMap.pipe(takeUntilDestroyed()).subscribe(params => {
      this.id.set(params.get('id') ?? '');
    });
  }
}
```

При `/books/b9` увидите `Книга b9`. После перехода к `/books/b10` заголовок должен измениться. `takeUntilDestroyed()` здесь вызывается в constructor, где доступен injection context. Он завершает подписку вместе с компонентом. Observable пока воспринимайте как источник последовательных значений, подробнее разберём его при HTTP.

Для query-параметра используйте `route.queryParamMap`, а изменение выражайте навигацией: `router.navigate([], { relativeTo: route, queryParams: { category: 'network' }, queryParamsHandling: 'merge' })`. `merge` сохраняет другие параметры; значение `null` удаляет выбранный. URL не является доверенным вводом: пользователь может написать любой статус или ID. Проверяйте union статуса и задавайте безопасное значение по умолчанию.

## Две разные ошибки

Неизвестный путь `/nothing/here` означает отсутствие правила маршрутизации. Путь `/issues/missing` соответствует правилу детали, но записи с таким ID нет. Для второго случая нужен текст «Заявка не найдена» и ссылка назад. Редирект любого отсутствующего ID без объяснения скрывает проблему и осложняет диагностику. Позднее отсутствие записи подтвердится HTTP 404.

Прямая загрузка пути обращается сначала к серверу документа. Dev server Angular поддерживает выдачу приложения для клиентских маршрутов. При настоящем размещении сервер тоже должен отдавать начальный HTML для таких URL. Настройка клиентского wildcard не исправит серверный 404 до загрузки JavaScript. Различайте эти уровни при проверке перезагрузки.

## Мост от Java

Router похож на таблицу маршрутов Spring MVC лишь задачей сопоставления URL. Он создаёт браузерные компоненты и не обеспечивает доступ к серверным данным. Guard в Angular может улучшать навигацию, но пользователь способен вызвать API напрямую. Права, ограничения и проверка ID остаются ответственностью сервера.
