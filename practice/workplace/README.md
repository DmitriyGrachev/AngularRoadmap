# Service Desk: рабочая практика

Отдельное действующее Angular-приложение для шести факультативных тикетов. Начните с чтения незнакомого кода, затем выберите тикет в разделе тренажёра на сайте курса. Это исходная рабочая версия продукта: запрошенные тикетами возможности ещё не реализованы.

## Запуск из корня репозитория

```text
npm run practice:workplace
npm run test:workplace
npm run build:workplace
```

На Windows PowerShell при ограничении запуска `npm.ps1` используйте `npm.cmd` вместо `npm`. Приложение: [http://127.0.0.1:4305](http://127.0.0.1:4305). Ни Java API, ни внешний аккаунт для этой практики не требуются. Зависимости уже заданы в корневом package.json; при первом запуске используйте обычную установку зависимостей проекта.

## Что уже работает

- Очередь из 18 обращений; поиск по номеру, теме и отделу; фильтр статуса; страницы по шесть записей.
- Состояние списка в URL, открытие карточки и возврат с сохранением параметров. Пример: `/requests?q=VPN&status=open`.
- Редактирование темы и описания, клиентская и серверная валидация, блокировка повторного сохранения, сохранение ввода при отказе.
- Отдельные состояния загрузки, отсутствующей карточки, ошибки и пустой выдачи.
- 14 автоматических проверок сервиса, нормализации URL и страниц с настоящим локальным API.

## Граница локального API

`DeskApi` — сервис в памяти, моделирующий асинхронный контракт. Это **не HTTP**: в Network не будет запросов списка или PATCH. Чтение списка занимает 350 мс, карточки — 250 мс, запись — 500 мс. RxJS-подписка запускает операцию; отмена подписки отменяет таймер. В настоящем HTTP отмена ожидания клиентом **не гарантирует** отмену уже начатой серверной записи.

Данные живут в экземпляре сервиса до полной перезагрузки страницы. Каждый браузерный контекст имеет независимые данные. Перезагрузка восстанавливает seed; не используйте её для проверки устойчивого хранения. Здесь нет авторизации, конкурентного редактирования, реального сетевого транспорта или базы данных — эти границы не входят в тикеты.

Внизу страницы раскройте «Среда для воспроизведения ошибок». «Следующее чтение списка: 503» действует на следующий подписанный запрос списка; после нажатия измените поиск, статус или страницу. Повторная отправка совершенно того же URL в baseline не инициирует загрузку. «Следующее сохранение: 503» действует на следующий PATCH. Флаг ошибки потребляется при подписке, даже если запрос затем отменён. После единственного отказа следующие запросы снова работают.

422 можно получить, отправив тему из пяти пробелов: текущая клиентская проверка длины её пропускает, сервис отклоняет. Это осознанный сценарий ticket-03. API также уже принимает status и assignee, проверяет принадлежность исполнителя команде и требует исполнителя для in-progress.

| `src/app/app.ts` | Корневой layout, маршруты, управление воспроизводимыми отказами |

## Как выполнять тикеты

Тикеты `ticket-01`…`ticket-06` находятся в `content/training/tickets.json` и связаны с уроками. Каждый можно начать с исходной версии; зависимости между ними не обязательны. Если выполняете последовательно, сохраняйте уже добавленные возможности и расширяйте проверки их пересечений. Перед первым изменением сделайте собственную копию `practice/workplace` или локальный коммит, если используете Git. Команды тренажёра не сбрасывают вашу работу.

Сначала запишите прогноз и свою попытку на сайте курса. После этого откроются объяснение и новое требование. В отчёте нужны: воспроизведение до изменения, затронутые границы, diff, тесты, ручные сценарии и оставшиеся ограничения. Успешные baseline-тесты не доказывают выполнение тикета — добавьте проверки его критериев. Для этих шести рабочих задач нет автоматического выставления оценки через `learn check`.

Восемь упражнений `review-01`…`review-08` — самостоятельные фрагменты PR с полным существенным контекстом. Их не нужно применять к baseline. Некоторые изменения корректны: ответ «accept» требует аргумента так же, как «changes».

После собственной попытки можно открыть [рекомендации приёмки](../../author/workplace/ACCEPTANCE.md). Там приведены проверочные сценарии и направления решений, а не уже изменённые файлы ученика.
