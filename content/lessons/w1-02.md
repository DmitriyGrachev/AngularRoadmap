# CSS: почему карточка выглядит именно так

**Результат:** вы определяете применённое правило CSS, исправляете переполнение и собираете панель действий, работающую на узком экране. Нужно знать [структуру HTML и DOM](/lessons/w1-01). Отведите 30 минут механизму, 20 примеру, 45 практике, остальные — прогнозу и объяснению.

## Рабочая ситуация и прогноз

Карточка хорошо выглядит на большом мониторе, но справа появляется горизонтальная прокрутка на телефоне. Уменьшение шрифта случайно скрывает симптом. Нам нужно найти причину размера.

```css
.card { width: 300px; padding: 20px; border: 2px solid black; }
```

Какова внешняя ширина без `margin`: 300 или 344 пикселя? Что изменится после `box-sizing: border-box`? Запишите ответы. Пиксель CSS — единица размеров интерфейса; он не обязан совпадать с одним физическим пикселем дисплея.

## Как браузер выбирает оформление

CSS — набор правил оформления. В правиле `.card { padding: 20px; }` селектор `.card` выбирает элементы с классом `card`, свойство `padding` задаёт внутренний отступ, значение содержит число и единицу. Селектор `p` выбирает все абзацы, `#result` — элемент с таким `id`. Классы удобны для повторяемого оформления нескольких карточек. Имя класса само по себе ничего не рисует: нужно соответствующее правило и подключённый stylesheet, то есть таблица стилей.

В HTML связь задаёт `<link rel="stylesheet" href="styles.css">`. Путь вычисляется относительно HTML-файла. Если таблица не загрузилась, сначала проверьте путь и Network, а не меняйте специфичность селектора. Браузер имеет стандартные стили: поэтому заголовки крупнее абзацев даже без вашего CSS.

Каскад разрешает конфликт нескольких деклараций. В обычных авторских правилах без специальных слоёв и `!important` сначала имеет значение специфичность, затем порядок при равной специфичности. Класс специфичнее селектора элемента; правило с `id` специфичнее класса. «Последнее правило всегда побеждает» неверно. Не лечите конфликт добавлением всё более длинных селекторов: найдите конкурирующее правило. В DevTools зачёркнутая декларация показывает проигравшее значение, а Computed — итоговое вычисленное.

Некоторые свойства наследуются от родителя: например, цвет текста и семейство шрифта. Отступы и границы обычно не наследуются. `body { color: ... }` может изменить текст глубоко в дереве, но `body { margin: ... }` не добавит такой же внешний отступ каждой карточке. Кнопки не во всех браузерных стилях наследуют шрифт так, как ожидается; `button { font: inherit; }` делает намерение явным.

## Прямоугольники и раскладка

Box model — модель прямоугольника: содержимое, внутренний отступ `padding`, граница `border`, внешний отступ `margin`. При стандартном `content-box` ширина относится к содержимому. В прогнозе итог 300 + 40 + 4 = 344. При `border-box` содержимое сжимается так, чтобы `width` включала padding и border; итог становится 300. Margin остаётся снаружи в обоих случаях. Отступ сверху у соседних обычных блоков иногда схлопывается; для расстояния между элементами flex-панели используйте `gap`, который выражает нужный промежуток напрямую.

`width: 100%` с большим padding при `content-box` легко превышает доступную ширину. `max-width` ограничивает карточку сверху, сохраняя возможность сжиматься. `margin-inline: auto` распределяет свободное место по бокам. Длинная непрерывная строка тоже может переполнить контейнер; проверять нужно реальное содержимое, а не только пустые блоки.

Flexbox распределяет дочерние элементы контейнера вдоль главной оси. `display: flex` включается на панели, а не на каждой кнопке. `gap` задаёт промежутки, `flex-wrap: wrap` разрешает перенос на следующую строку. Без переноса суммарная минимальная ширина детей может не уместиться. `justify-content` располагает содержимое вдоль главной оси, `align-items` — поперёк. Для двух кнопок этого достаточно; сеточная система или библиотека здесь не нужна.

## Мост от Java

У CSS нет прямого аналога вызова Java-метода «нарисовать карточку». Правила описывают ограничения, браузер вычисляет результат для всего дерева. Каскад отдалённо напоминает разрешение нескольких настроек, но наследование CSS не является наследованием Java-классов. Родительский DOM-элемент не превращается в базовый класс своих детей. Поэтому полезнее исследовать конкретное вычисленное свойство, чем переносить на CSS правила Java-полиморфизма.

## Разобранный пример

При работающем `npm.cmd run practice:web` откройте [пример CSS](http://127.0.0.1:4301/foundations/web-basics/examples/css.html), файл `practice/foundations/web-basics/examples/css.html`. Карточка имеет внутренний отступ 24px и ширину не более 640px; две кнопки разделяет 12px. На узком экране карточка помещается в body с боковыми отступами 16px.

В Elements выберите `.card`. Временно снимите `box-sizing: border-box` и задайте `width: 100%`: наблюдайте, как padding и border добавляются к ширине. Верните правило. Затем отключите `display: flex` у `.actions`: кнопки вернутся к обычному потоку, а flex-gap потеряет смысл. Это изменение одного условия помогает связать свойство и эффект. Временные эксперименты запишите, затем внесите нужное исправление в IDE.

## Практика в IDE

Упражнение `w1-02-ex1`: редактируйте `practice/foundations/web-basics/w1-02-ex1/styles.css`, HTML используйте для чтения. Откройте [заготовку](http://127.0.0.1:4301/foundations/web-basics/w1-02-ex1/index.html). Найдите намеренный внешний отступ 80px и причину переполнения при `width: 100%`. Сделайте карточку с максимальной шириной 680px, удобными внутренними отступами и панелью с переносом. Подберите достаточный контраст и видимую рамку клавиатурного фокуса. Не используйте `overflow-x: hidden` как способ спрятать ошибку ширины.

Проверьте через responsive mode DevTools ширины 375 и 1280px. Tab должен последовательно показывать фокус на кнопке и ссылке. Эта работа проверяется визуально и объяснением, автоматический отчёт не создаётся.

## Критерии

- На обеих ширинах страница не прокручивается горизонтально, текст и действия доступны.
- Панель использует flex-контейнер и понятные промежутки, перенос не обрезает действия.
- Причина исходного дефекта объяснена через margin и box model; исправление сохранено в файле.
- Фокус виден при Tab, основной текст читается без увеличения страницы.
