# Angular Learning Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Статус:** после подготовки плана пользователь отдельно разрешил реализацию. Фактический результат, отличия от предполагаемых путей и доказательства проверок фиксируются в [отчёте реализации](../../implementation-status.md).

**Goal:** Подготовить личный учебный сайт и отдельную среду практики, в которых Java-разработчик последовательно осваивает JavaScript, TypeScript и Angular для рабочих задач.

**Architecture:** Локальный сайт Angular отображает материалы из Markdown и единого каталога курса. Упражнения запускаются независимо в IDE; результаты проверок переносятся на сайт через файл отчёта. Прогресс хранится в браузере с экспортом и импортом; Java API подключается как учебная часть проекта на четвёртой неделе.

**Tech Stack:** Angular, TypeScript, HTML/CSS, npm, Markdown, Node.js для учебных команд и проверок материалов; Java для подготовленного API. Версии выбираются в задаче 1 по совместимости. Сайт не требует серверной базы данных.

**Spec:** [Программа обучения и устройство платформы](../specs/2026-10-20-angular-learning-platform-design.md).

## Global Constraints

- Отдельное указание пользователя начать реализацию получено после утверждения плана.
- Учебная нагрузка: 6 недель × 15 обязательных часов = 90 часов; резерв до 30 часов.
- Подготовка сайта и материалов не входит в учебные часы пользователя.
- Основные объяснения и интерфейс — на русском; технические названия сопровождаются английскими эквивалентами.
- Один каталог курса задаёт стабильные ID, порядок, зависимости, готовность и способы проверки.
- Ошибка ученического кода не мешает запуску сайта, чтению уроков и экспорту прогресса.
- Команды обслуживания не изменяют ученические решения и личный прогресс.
- Открытие урока, успешный запуск тестов и понимание темы учитываются отдельно.
- Неполная, прерванная или пустая проверка не даёт успешный результат.
- Сайт не запускает команды на компьютере через скрытый мост; импорт отчёта выполняет пользователь.
- Первая версия рассчитана на одного человека и локальную работу.

## Review Focus

1. Неполный отчёт: обязательная проверка отсутствует, пропущена или запуск прерван — успех не присваивается. Проверяет задача 4.
2. Старый или повторный импорт — новые данные не теряются, дубликаты не увеличивают прогресс. Проверяет задача 5.
3. Повреждённое хранилище или превышение доступного объёма — интерфейс объясняет проблему, не сообщает о несостоявшемся сохранении. Проверяет задача 5.
4. Изменённое учеником упражнение — проверки материалов не возвращают starter и не перезаписывают работу. Проверяют задачи 4 и 10.
5. Поздний HTTP-ответ или серверная ошибка формы — интерфейс не подменяет актуальные данные и не стирает ввод. Проверяют задачи 8 и 9.

## Границы первого выпуска

Первый пригодный для занятий выпуск включает весь учебный материал недели 1, работающий сайт, независимую практику, проверки первых автоматизируемых упражнений и сохранение прогресса. Отдельный пилот из одного урока используется для проверки учебного сценария; он ещё не считается готовой неделей.

Недели 2–6 выпускаются последовательно, каждая полностью готова до начала её прохождения. Их наличие в карте курса не означает наличие готовой теории.

Оценки сроков разработки намеренно не привязаны к шести учебным неделям: подготовка материалов — отдельная работа.

## Контракты между задачами

Полные правила данных описаны в спецификации. Здесь зафиксированы имена, на которые опираются задачи.

- `LessonMeta`: `id`, `week`, `order`, `title`, `minutes`, `contentPath`, `prerequisites`, `readiness`, `exerciseIds`.
- `ExerciseMeta`: `id`, `lessonId`, `assessmentRevision`, `mode`, `workspacePath`, `editablePaths`, `requiredCheckIds`, `targetKey`.
- `Curriculum`: `schemaVersion: 1`, `lessons`, `exercises`.
- `AssessmentReport`: `schemaVersion: 1`, `runId`, `exerciseId`, `assessmentRevision`, `finishedAt`, `outcome`, `checks`.
- `ProgressSnapshot`: `schemaVersion: 1`, `lessonRecords`, `attempts`.
- `validateCurriculum(value: unknown): ValidationResult<Curriculum>`.
- `validateReport(value: unknown, curriculum: Curriculum): ValidationResult<AssessmentReport>`.
- `mergeProgress(current: ProgressSnapshot, incoming: ProgressSnapshot): MergePreview`.
- `recommendNext(curriculum: Curriculum, progress: ProgressSnapshot): Recommendation | null`.

`ValidationResult<T>` содержит либо проверенное значение, либо список понятных ошибок. `MergePreview` содержит предполагаемый результат и список конфликтов, которые нужно разрешить перед сохранением. Названия не определяют способ реализации Angular-компонентов.

## Порядок исполнения и остановка

Последовательность: 1 → 2 → 3 → 4 → 5 → 6 → проверка первого выпуска; далее 7 → 8 → 9 → проверка полного курса.

Подготовку схем и части текстов можно выполнять параллельно после фиксации каталога. Общие контракты, прогресс и runner изменяются последовательно, чтобы не расходились форматы.

Каждая завершённая задача проходит узкую проверку по своему результату. При наличии Git изменения можно фиксировать отдельными локальными коммитами; создание удалённого репозитория, публикация и отправка изменений не относятся к этому плану.

Переход к реализации разрешён пользователем. Исходный список задач сохранён как спецификация; фактическое выполнение и ограничения описаны в отчёте реализации.
